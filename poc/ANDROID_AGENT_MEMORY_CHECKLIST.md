# Android 장기 메모리·군집 기능 구현 체크리스트

이 문서는 Android POC를 온디바이스 Personal Wiki 에이전트로 확장하기 위한 기능별 작업 목록이다. 먼저 L2 사건 군집의 오결합을 줄인다. 이후 L1 원문 기억과 L3 상태 위키, 개인화를 연결한다. 현재 요구사항은 [PRD](SLM_Wiki_PRD.md), 앱 사용법은 [Android POC 안내](android/README.md)를 따른다.

- `[x]`는 현재 실험 앱에 기능이나 테스트가 구현되어 있다는 뜻이다. 품질·속도·실기기 합격을 뜻하지 않는다.
- `[ ]`는 구현 또는 검증이 남은 항목이다. 상위 항목이 미완료여도 완료한 하위 항목은 표시한다.
- 실기기 음성 인식·속도·메모리와 실제 자료의 군집 품질은 미판정이다. PC의 v3 잠정 시험 결과를 현재 APK의 성능으로 사용하지 않는다.
- 이전 생활 기능의 코드가 존재하는 것과 현재 실험 화면에서 그 기능을 사용할 수 있는 것은 구분한다. 특히 정답 라벨은 평가용이며 사용자 군집 정정이 아니다.
- EmbeddingGemma 2 영상은 제작자의 설명을 확인했다. 영상과 Colab 노트북 본문은 직접 열지 못했으므로 세부 구현은 후속 실험 전에 확인한다. 영상의 검색 실험 수치를 현재 앱의 사건 군집 성능으로 사용하지 않는다.

## 메인 1. 기록 입력과 원문 관리

- [x] 문서·직접 입력·음성 인식 글을 하나의 새 실험 목록에 저장한다. 근거: [실험 저장소 테스트](android/app/src/androidTest/java/com/heecchoi/slmwikipoc/ExperimentStoreTest.kt).
  - [x] TXT·Markdown·텍스트 PDF를 선택해 가져온다. 근거: [Android POC 안내](android/README.md#입력과-군집-실행).
  - [x] 접근을 허용한 공유 저장소를 스캔하고 제외 사유와 진행 상태를 표시한다. 근거: [실험 처리](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentViewModel.kt).
  - [x] 직접 입력한 글을 저장하고 수정한다. 근거: [실험 저장소](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentStore.kt).
  - [x] 지원 기기에서 기기 내 한국어 음성 인식 결과를 확인·수정한 뒤 저장한다. 실기기 인식 품질은 별도 검증이 필요하다. 근거: [음성 인식](android/app/src/main/java/com/heecchoi/slmwikipoc/OnDeviceSpeech.kt), [입력 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt).
- [x] 목록에는 제목을 표시하고 항목을 눌러 전체 내용을 확인한다. 근거: [입력 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt).
- [x] 새 실험과 이전 생활 기록을 분리한다. 스캔한 기기 원본을 수정하거나 삭제하지 않는다. 근거: [저장소 테스트](android/app/src/androidTest/java/com/heecchoi/slmwikipoc/ExperimentStoreTest.kt), [ADR 0002](../docs/adr/0002-isolate-clustering-experiment.md).
- [ ] 기록을 장기 메모리의 L1 원문 기억으로 확장한다.
  - [ ] 등록 시각과 실제 작성·발생 시각, 시간대와 시각의 출처를 구분한다. 출처 시각을 모르면 미상으로 둔다.
  - [ ] 원문 버전과 삭제·만료 상태를 관리한다.
  - [ ] 공유 글과 사용자가 허용한 알림을 L1 입력에 연결한다. 현재 새 알림 수집은 중지되어 있다.
  - [ ] 수정·삭제 후 오래된 파생 결과가 다시 나타나지 않게 한다.

- [x] 긴 본문을 조각으로 나누어 처리하고 군집용 대표 벡터를 만든다. 근거: [임베딩 처리](android/app/src/main/java/com/heecchoi/slmwikipoc/EmbeddingModel.kt), [조각 처리 테스트](android/app/src/test/java/com/heecchoi/slmwikipoc/ExperimentDomainTest.kt).
- [x] 입력 버전·모델·처리 방식이 같은 임베딩을 재사용한다. 근거: [실험 저장소](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentStore.kt), [실험 처리](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentViewModel.kt).
- [x] 진행 상태와 취소를 제공한다. 실패하거나 자원이 부족하면 일부 결과를 전체 결과로 표시하지 않는다. 근거: [실험 처리](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentViewModel.kt), [입력 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt).
- [ ] 현재 APK 모델과 군집 설정의 기준 성능을 고정 자료로 측정한다.
  - [ ] 모델·토크나이저 해시, 처리 버전, 거리 기준과 앱 커밋을 기록한다.
  - [ ] 합성 자료와 실생활 자료의 결과를 따로 기록한다.
  - [ ] [v3 PC 실험](embedding/RESULTS_v3.md)의 잠정 수치와 현재 APK 측정값을 구분한다.
- [ ] PC와 Android의 입력·임베딩 처리를 같은 합성 자료로 비교한다.
  - [ ] 앱에서 사용하는 이름을 가리지 않은 원문을 공통 기준으로 둔다. v3 합성 자료의 알려진 인물 이름 가리기는 별도 대조군으로 측정한다.
  - [ ] 짧은 본문, 긴 본문, 긴 제목을 포함해 토큰 처리와 분할·평균화, 벡터와 군집 결과를 비교한다. 차이가 있으면 원인을 확인한 뒤 해석한다.
  - [ ] 비교한 모델·토크나이저 해시와 처리 버전을 기록한다. 개인 원문과 정답은 PC로 옮기지 않는다.
- [ ] L1 원본 벡터를 장기 메모리 용도로 확장한다.
  - [ ] 검색용 조각 벡터와 군집용 원본 대표 벡터를 구분해 저장한다.
  - [ ] 원문·모델·처리 버전과 연결하고 개인화 결과로 원본 벡터를 덮어쓰지 않는다.

## 메인 3. L2 사건 군집 품질 개선

- [x] 거리 기준을 조절하고 명시적으로 군집을 다시 실행한다. 근거: [결과 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt).
- [x] 정답 주제가 있는 기록 쌍을 대상으로 정밀도·재현율·F1을 계산한다. 근거: [품질 계산](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentStore.kt), [품질 계산 테스트](android/app/src/test/java/com/heecchoi/slmwikipoc/ExperimentDomainTest.kt).
- [ ] 구체적인 사건을 L2 군집의 기준으로 적용한다.
  - [ ] 같은 예약·진료·주문의 전후 기록은 한 사건으로 묶는다.
  - [ ] 같은 사람이나 주제라도 별도 사건이면 분리한다.
  - [ ] 관계가 불명확하면 잘못 합치기보다 분리하거나 확인 대상으로 남긴다.
- [ ] 현재 모델의 같은 벡터로 군집 후보를 비교한다.
  - [ ] 기존 평균 연결과 거리 기준을 기준선으로 재현한다.
  - [ ] 개발 자료에서 거리 기준과 보수적인 연결 방식 후보를 비교한다.
  - [ ] 주문번호·날짜처럼 원문에서 명확히 확인되는 단서를 결합한 방식을 모델 단독 방식과 비교한다.
  - [ ] 모호하거나 충돌하는 단서를 같은 사건이라는 근거로 사용하지 않는다.
- [ ] 선택된 L2 방식을 새 실험 앱에 연결한다.
  - [ ] 모델 단독 결과와 단서 결합 결과를 구분한다. 이전 생활 기능의 [단서 결합 코드](android/app/src/main/java/com/heecchoi/slmwikipoc/LifeDomain.kt)는 새 실험 화면의 구현 완료로 계산하지 않는다.
  - [ ] 한 기록은 하나의 L2 사건에 속하도록 한다.
  - [ ] 자동 군집 결과와 사용자 정정을 별도로 보관한다. 기준은 [ADR 0001](../docs/adr/0001-separate-automatic-and-user-clusters.md)을 따른다.
- [ ] 현재 모델과 군집 방식으로 부족할 때만 PC 재학습·모델 교체를 검토한다.
  - [ ] 기존 v1·v2·v3 자료에서 회귀를 비교한다. 이미 결과를 확인한 자료는 독립된 최종 시험이 아니라 회귀 참고 자료로 표시한다.
  - [ ] Android 변환 후 기존 모델과 같은 자료로 품질을 대조한다.
- [ ] 재학습이 필요하면 기존 `TripletLoss`와 `MultipleNegativesRankingLoss`를 같은 버전의 합성 학습 자료로 비교한다.
  - [ ] 기존의 명시적인 어려운 오답을 보존하고 검색용과 군집용 입력 형식을 각각 학습·추론에 맞춘다.
  - [ ] 같은 배치에서 같은 사건의 다른 기록이나 질문에 답할 수 있는 문단이 오답으로 쓰이지 않도록 정답 관계를 확인한다. 문자열 중복 제거만으로 의미가 같은 기록까지 걸러졌다고 판단하지 않는다.
  - [ ] 실제 배치 크기·기울기 누적·손실 설정과 학습 시간을 함께 기록한다. 기존 배치 크기 1에서 기울기를 8회 누적해도 8개 기록이 한 배치의 오답으로 비교되지는 않는다.
  - [ ] 개발 자료로 학습 후보와 거리 기준을 정하고 별도의 고정 시험 자료로 최종 확인한다. 시험 결과를 보고 후보를 바꾸면 해당 자료는 개발용으로 전환하고 새 시험 자료를 준비한다.
  - [ ] 이 후속 학습·평가의 자동 실행은 모델 준비를 포함해 별도 2시간 이내로 제한한다. 시간 안에 마치지 못하면 미완료로 기록한다.

## 메인 4. 군집 결과와 평가 화면

- [x] 군집별 기록 수와 제목, 미분류 수를 표시한다. 근거: [결과 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt).
- [x] 군집을 열어 전체 기록을 확인하고 PCA 지도에서 점을 선택한다. 근거: [결과 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt), [PCA 지도](android/app/src/main/java/com/heecchoi/slmwikipoc/MainActivity.kt).
- [x] PCA 지도 확대·이동과 마지막 성공 결과의 재시작 후 복원을 지원한다. 근거: [PCA 지도](android/app/src/main/java/com/heecchoi/slmwikipoc/MainActivity.kt), [저장소 테스트](android/app/src/androidTest/java/com/heecchoi/slmwikipoc/ExperimentStoreTest.kt).
- [x] 입력이나 거리 기준이 바뀌면 이전 결과에 재실행이 필요하다고 표시한다. 근거: [실험 처리](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentViewModel.kt).
- [x] 새로 계산한 임베딩 시간, 군집 시간과 재사용 건수를 표시한다. 근거: [결과 화면](android/app/src/main/java/com/heecchoi/slmwikipoc/ExperimentScreen.kt).
- [ ] 사건 단위 평가 기능을 보강한다.
  - [ ] 기록의 사건 정답을 기기 안에서 입력·수정한다. 기존 정답 주제 입력을 사건 정답 평가에 맞게 확장한다.
  - [ ] 오결합과 과분할된 기록을 원문과 함께 비교한다.
  - [ ] 전체 사건 쌍 F1, 오결합 수, 놓친 관련 쌍 수와 평가 대상 수를 표시한다.
  - [ ] 정답이 없는 기록과 정량 판정에 사용한 기록을 구분한다.
- [ ] 실생활 검색 평가 기능을 새 실험 화면에 추가한다.
  - [ ] 사용자가 기기에서 검색 질문과 정답 근거를 입력·수정하고 확인한다. 현재 실험 화면에는 이 평가 기능이 없다.
  - [ ] 기준선과 후보에 같은 질문·근거를 적용해 Recall@5와 MRR을 따로 표시한다. Recall@5는 상위 5개 결과에 정답 근거가 포함된 질문의 비율이다. MRR은 정답 근거가 처음 나온 순위의 역수를 평균한 값이다.
  - [ ] 질문·정답과 원문은 기기에 보관하고 자동으로 외부에 전송하지 않는다.
- [ ] 사용자 정정 기능을 새 실험 화면에 추가한다.
  - [ ] 잘못 합친 기록을 분리하고 같은 사건의 기록을 합치거나 이동한다.
  - [ ] 정정 내용이 이후 재군집에서 유지되는지 확인한다.

## 메인 5. 평가 자료와 합격 판정

- [ ] 합성 자료의 개발용·고정 시험용을 준비한다.
  - [ ] 자료의 버전·해시·사람 검수 상태를 기록한다.
  - [ ] 같은 사람·주제·날짜의 다른 사건과 변경·취소 사례를 포함한다.
  - [ ] 개발 자료로 후보와 거리 기준을 선택하고 시험 자료는 최종 비교에 사용한다.
- [ ] 실생활 기록 **50~100건**을 목표로 기기 안에서 사건 정답을 검수한다.
  - [ ] 개발용과 시험용을 사건 단위로 분리한다.
  - [ ] 원문과 정답을 자동으로 외부에 전송하지 않는다.
  - [ ] 시험 자료의 관련 쌍과 무관 쌍이 각각 50개 미만이면 예비 결과로 남긴다.
- [ ] 합성 자료와 실생활 자료를 각각 평가한다.
  - [ ] 전체 사건 쌍 F1 **0.80 이상**을 목표로 한다.
  - [ ] 같은 시험 자료의 기존 기준선보다 오결합이 늘어난 후보는 채택하지 않는다.
  - [ ] 정밀도·재현율·과분할과 대표 실패 사례도 함께 보고한다.
  - [ ] 정답 검수나 표본이 부족하면 미판정으로 둔다.
- [ ] 검색 성능의 회귀도 별도로 평가한다.
  - [ ] 동일한 고정 검색 시험 자료에서 후보의 Recall@5가 현재 기준선보다 하락하면 통합 채택을 보류한다. MRR은 보조 지표로 기록한다.
  - [ ] 사람이 근거를 검수한 실생활 시험 질문을 20개 이상 기기 안에서 고정한다. 부족하면 실생활 검색 판정을 보류하고 결과에 소표본의 한계를 적는다.
  - [ ] 합성 검색과 실생활 검색 결과를 구분한다. 검색 평가를 수행할 수 없으면 통합 채택을 보류한다.
- [ ] 첫 PC 자동 실험은 준비·벡터 계산·후보 비교를 합쳐 **2시간 이내**로 제한한다.
  - [ ] 사람의 정답 검수 시간은 별도로 기록한다.
  - [ ] 시간 한도에 도달하면 미완료 상태와 중단 지점을 남긴다.

## 메인 6. L3 상태 위키

- [ ] 한 기록이 여러 L3 주제에 속하도록 한다.
  - [ ] 주 소속과 추가 소속을 구분한다.
  - [ ] L2 사건 단일 소속과 혼동하지 않도록 표시한다.
- [ ] 주제별 현재 상태 슬롯과 시간순 변경 이력을 저장한다.
  - [ ] 각 상태 값과 변경 이력에서 원문 근거를 열 수 있게 한다.
  - [ ] 저장된 슬롯과 이력으로 위키 화면을 만든다.
- [ ] 명확한 변경은 새 상태를 먼저 반영한다.
  - [ ] 이전 값과 이전 근거를 보존한다.
  - [ ] 변경 배지와 즉시 되돌리기를 제공한다.
  - [ ] 관계가 모호하면 기존 상태를 유지하고 사용자 확인을 요청한다.
- [ ] 삭제·만료된 원문의 값과 근거가 위키에 남거나 부활하지 않게 한다.

## 메인 7. 단계별 개인화

- [ ] **1단계 — 별칭과 사용자 정정**
  - [ ] 사용자가 확인한 개인 개체·별칭을 검색에 활용한다.
  - [ ] 군집 입력에서 개인 개체를 가리되 원문은 보존한다.
  - [ ] 합친 기록과 분리한 기록을 Must-Link·Cannot-Link 제약으로 관리한다.
  - [ ] 재군집 후에도 사용자 제약을 보존하고 충돌은 확인하도록 한다.
- [ ] **2단계 — 거리와 검색 가중치 보정**
  - [ ] 확인된 정정과 피드백을 기기 안에서 누적한다.
  - [ ] 사건·주제 거리 기준과 혼합 검색 가중치를 보정한다.
  - [ ] 보정 전후 품질과 오결합을 비교한다.
- [ ] **3단계 — 로컬 어댑터**
  - [ ] 충전·유휴 상태에서 캐시된 원본 벡터로 `768 → 32 → 768` 경량 어댑터를 학습한다.
  - [ ] 기반 모델과 원본 벡터는 수정하지 않는다.
  - [ ] 기본 검증 셋과 사용자 확정 정답 쌍으로 이전 가중치와 후보를 각각 비교한다.
  - [ ] 어느 쪽이든 F1이 하락하거나 오결합이 늘면 후보를 폐기한다.
  - [ ] 검증 자료가 부족하면 후보 활성화를 보류한다.
  - [ ] 1,000 Triplet 기준 CPU 5초·가중치 1MB·추가 PSS 50MB 이하 목표를 실기기에서 측정한다. MB는 1,000,000바이트다.
- [ ] 별칭·정정 제약·어댑터 가중치와 안전 게이트 이력을 수동 내보내기·복원에 포함한다.
