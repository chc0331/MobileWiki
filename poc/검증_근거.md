# SLM Wiki POC 검증 근거

공식 자료 확인 기준일: 2026-10-27 · 로컬 실험 확인일: 2026-10-28. 이 문서는 [상세 PRD](./SLM_Wiki_PRD.md)와 [한 페이지 요약](./README.md)의 기술적 전제를 확인하는 관리 문서다. 요구사항과 합격 기준의 정본은 상세 PRD다. 공식 자료에서 확인한 사실과 이 POC에서 측정한 내용을 구분한다.

## 1. 확인 범위와 읽는 법

모델 카드는 제작자가 공개한 모델의 설명서다. 지원 언어와 사용 조건을 확인하는 근거지만 한국어 개인 메모의 처리 품질을 보장하지는 않는다. 런타임은 모델을 실제로 실행하는 프로그램이다. 런타임의 Android 지원과 특정 모델 파일의 정상 실행도 별도로 확인해야 한다.

공식 모델 카드·라이선스·Android 문서와 학습 도구 문서를 확인했다. 개발 PC에서 로컬 Qwen3 8B의 전체 합성 데이터 생성과 EmbeddingGemma 2의 텍스트 임베딩·LoRA 학습·고정 평가를 실행했다. 수치는 사람 검수 전 잠정치이며 [실험 결과](embedding/RESULTS.md)에 기록했다. Hugging Face Hub 업로드·재현 시험과 스마트폰 측정은 아직 하지 않았다. PC 결과로 앱의 모델 용량·메모리·응답 시간 합격을 주장하지 않는다.

EmbeddingGemma 2의 텍스트 전용 LiteRT 배포 ID는 `litert-community/embeddinggemma-2-text-270m-litert-lm`이다. 검색 질문·문서·군집에 사용하는 입력 지시문이 다르다. 같은 임베딩 모델을 여러 기능에서 쓰더라도 각 기능에 맞는 입력 처리를 검증해야 한다. [배포 카드](https://huggingface.co/litert-community/embeddinggemma-2-text-270m-litert-lm), [공식 임베딩 API 안내](https://developers.google.com/edge/litert-lm/embedding_models)

## 4. 실행 도구와 자원 판정의 근거

LiteRT-LM은 Android Kotlin API와 CPU 백엔드를 제공한다. 생성 모델 외에 EmbeddingGemma 2를 실행하는 임베딩 API도 있다. llama.cpp에는 Android 빌드와 샘플 경로가 있다. ONNX Runtime은 Android 배포를 지원한다. 이 도구의 지원 범위와 후보 모델별 변환·속도·메모리 검증은 별개의 확인 항목이다. [LiteRT-LM Android](https://developers.google.com/edge/litert-lm/android), [llama.cpp Android](https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md), [ONNX Runtime 모바일](https://onnxruntime.ai/docs/get-started/with-mobile.html)

앱에 필요한 전체 모델 묶음의 크기를 계산할 때는 가중치뿐 아니라 토크나이저·설정·필수 어댑터도 포함해야 한다. 두 모델이 차지하는 저장 공간, 실행 중 메모리, 메모·색인이 차지하는 공간도 각각 기록한다. 부분 파일의 표시 용량은 전체 합계로 취급하지 않는다.

같은 모델도 양자화 방식, 문맥 길이, 런타임 버전, CPU 스레드 수에 따라 결과가 달라진다. 공개 벤치마크는 후보 선정에 참고하고 합격 여부는 PRD의 기준 기기에서 시험해 판단한다. 선택한 파일의 해시와 버전을 고정한 뒤 앱 전체의 시작·검색·생성·대량 처리 경로를 측정해야 한다. [Gemma 변환물의 조건별 측정](https://huggingface.co/litert-community/Gemma3-1B-IT), [Qwen 변환물의 조건별 측정](https://huggingface.co/litert-community/Qwen3-0.6B)

## 5. Android 요구사항에 영향을 주는 사실

**PDF 가져오기:** Android 12는 API 31이다. PDF 페이지 이미지 표시와 글자 추출은 별도 기능이다. `PdfRenderer.Page.getTextContents()`는 API 35에서 추가됐다. `PdfRendererPreV.Page.getTextContents()`는 S Extensions 13에서도 제공되지만 모든 API 31 기기가 해당 확장을 갖춘 것은 아니다. 따라서 API 31~34 전체를 지원하려면 별도의 호환 가능한 추출기를 검증해야 한다. 추출한 한글·표·읽기 순서를 원문과 대조한다. 텍스트가 없는 스캔 PDF를 성공으로 처리하지 않는다. [공식 PDF API](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page#getTextContents()), [확장 API](https://developer.android.com/reference/android/graphics/pdf/PdfRendererPreV.Page#getTextContents())

**백업과 이전:** 일부 제조사의 기기 간 이전 경로는 `android:allowBackup="false"` 설정과 별도로 점검해야 한다. API 31 이상에서는 `dataExtractionRules`의 클라우드 백업과 기기 이전 규칙을 각각 확인한다. 저장 경로와 제외 규칙을 대조한다. 출시 대상 운영체제에서 제공하는 추가 이전 경로도 점검한다. 실제 기기에서 데이터가 복원·이전되지 않는지 시험해야 한다. [공식 백업 안내](https://developer.android.com/identity/data/autobackup)

**파일 선택과 내보내기:** Android의 저장소 접근 기능인 SAF에는 기기 저장소와 클라우드 제공자가 함께 참여한다. 앱에서 인터넷 권한을 제거해도 SAF를 통한 다른 제공자와의 파일 전달 경로는 남을 수 있다. `EXTRA_LOCAL_ONLY`는 네트워크 다운로드 없이 기기에서 이용할 수 있는 파일을 요청하는 옵션이다. 그 파일의 후속 클라우드 동기화까지 차단하는 보증으로 해석하지 않는다. 허용하는 가져오기·내보내기 경로는 PRD의 P2 예외와 일치해야 한다. [SAF 공식 안내](https://developer.android.com/guide/topics/providers/document-provider), [로컬 파일 옵션](https://developer.android.com/reference/android/content/Intent#EXTRA_LOCAL_ONLY)

**백그라운드 처리:** WorkManager의 반복 주기는 정확한 실행 시각을 보장하지 않는다. 배터리·충전·운영체제 최적화 조건에 따라 실행이 미뤄질 수 있다. 따라서 “하루 한 번 다시 묶기”는 주기 작업을 예약한다는 뜻으로 설명한다. 미완료 상태를 저장하고 재시작 후 이어 처리하는 동작도 평가한다. [공식 작업 예약 안내](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

## 6. 평가 데이터 생성과 적용 조건

PC용 임베딩 하위 POC에서는 로컬 `qwen3:8b`가 가상의 메모와 검색 질문을 만든다. 모델 가중치는 Ollama의 4비트 배포본이며 Apache 2.0 라이선스로 표시된다. 생성 때는 로컬 API의 JSON Schema 출력과 생각 과정 끄기 옵션을 사용한다. 모델 다운로드와 Hub 업로드에만 네트워크가 필요하다. 실제 사용자 메모는 생성 입력과 Hub 업로드 대상에서 제외한다. [Qwen3 8B 배포 카드](https://ollama.com/library/qwen3:8b), [Ollama 구조화 출력](https://docs.ollama.com/capabilities/structured-outputs), [생각 과정 설정](https://docs.ollama.com/capabilities/thinking)

사건 카드가 가족·날짜·주제와 찾을 사실을 정한다. Qwen은 같은 사건의 메모 4개와 질문 1개를 쓴다. 코드가 가상 인물 이름을 각 메모 제목에 붙이고 첫 메모의 답과 근거를 대조한다. 다른 메모에 답이 반복되면 해당 문장을 제거하고, 날짜나 근거 형식의 수정과 함께 내역을 남긴다. 이 자료로 텍스트 전용 EmbeddingGemma 2의 검색·묶음 어댑터를 학습한다. 학습·개발·고정 평가 자료는 가족·사건 단위로 분리한다. 자동 검사를 통과해도 사람이 질문 140개와 문서 쌍 100개를 원문과 대조하기 전에는 평가를 잠정치로 표시한다.

M2 Mac에서 텍스트 전용 EmbeddingGemma 2의 271,002,624개 파라미터와 768차원 출력을 확인했다. FP32·MPS에서 LoRA 250단계를 학습하고 어댑터 저장·재로딩을 확인했다. 어댑터는 텍스트 전용 기반 모델을 먼저 연 뒤 붙여야 했다. 별도로 시험한 MLX 경로는 첫 생성 토큰에서 Metal 커널 오류가 나서, 로컬 Qwen 실행에는 Ollama를 사용한다. 이미 로드된 Qwen3 8B로 예비 사건 10개를 만드는 데 약 331초가 걸렸다. 전체 실행 시간과 품질은 [실험 결과](embedding/RESULTS.md)에 기록했다. PC 측정은 Android 성능을 입증하지 않는다. [Google의 텍스트 전용 학습 안내](https://ai.google.dev/gemma/docs/embeddinggemma/fine-tuning-embeddinggemma-with-sentence-transformers), [Sentence Transformers 어댑터 안내](https://www.sbert.net/examples/sentence_transformer/training/peft/README.html)

## 7. 남아 있는 검증

기준 기기로 평가할 한국어 품질·CPU 지연·최대 메모리, 필수 파일을 포함한 모델 용량, PDF 추출기, 백업·이전 차단, 허용된 로컬 파일 경로는 실제 시험이 필요하다. 링크 확인 기록은 해당 시험의 통과 기록과 구분한다. 관리 문서이므로 교재용 문제·해설이나 별도 PDF는 만들지 않는다.

## 8. Hugging Face Hub 운영 원칙

Hub는 모델·데이터 저장소를 Git 기반 revision으로 관리한다. 모델 저장소와 데이터셋 저장소는 유형을 나누며 각 저장소에는 commit 이력이 남는다. 이 방식은 산출물 변경과 특정 시험에서 사용한 버전을 연결하는 데 적합하다. 큰 파일을 다루는 저장 방식·용량 한도는 사용 계정과 저장소 조건을 확인해야 한다. [Hub 저장소와 버전 관리](https://huggingface.co/docs/hub/main/repositories)

Dataset 저장소의 Dataset Card에는 데이터의 구성과 사용 조건을 설명한다. Dataset 저장소를 비공개로 생성할 수 있으며 비공개 데이터 접근에는 인증이 필요하다. 새 데이터 분할·설정을 추가할 수 있다. PRD는 합성 자료·검수 자료·개발 및 평가 분할을 한 Dataset에 정리하되, 평가 실행에서는 전체 revision SHA를 고정하는 방식으로 정했다. [Dataset 업로드·카드·비공개 설정](https://huggingface.co/docs/datasets/upload_dataset)

Model 저장소의 Model Card는 YAML 메타데이터로 기반 모델, 사용 데이터셋, 라이선스, 실행 라이브러리와 평가 결과를 기록할 수 있다. 모델을 추가 학습하거나 양자화하면 이를 원본 모델과 구분하고 기반 모델 및 데이터셋 저장소를 연결한다. Model Card 작성 여부와 기반 모델의 라이선스·파생 모델의 이용 조건은 별개다. [Model Card 메타데이터](https://huggingface.co/docs/hub/en/model-cards)

Hub 사용자 토큰에는 읽기와 쓰기 권한이 있으며 저장소 단위로 권한을 제한할 수 있다. PRD의 기본값은 비공개 저장소와 개발 PC의 최소 권한 토큰이다. 토큰을 코드·로그·앱에 넣지 않고 분실이나 유출이 의심되면 폐기한다. 개발 PC의 연결 계정이 `heecchoi`인 것은 확인했다. 이번 실험용 비공개 저장소는 사람 검수 전이라 만들지 않았다. 실제 요금·저장 한도는 확인하지 않았다. [사용자 토큰과 권한 범위](https://huggingface.co/docs/hub/security-tokens)

Hub에서 버전별 산출물을 관리하는 작업은 개발 환경의 네트워크 작업이다. 앱의 인터넷 사용과 개인 메모의 Hub 전송 여부는 이 작업과 별도로 확인한다. 비공개 저장소를 사용자 메모 업로드 허가로 간주하지 않는다. 공개 전환에는 출처·라이선스·비식별 여부를 사람이 확인해야 한다.
