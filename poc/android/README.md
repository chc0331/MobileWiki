# Android 생활 기록·문서 군집 POC

Android 12 이상 ARM64 기기에서 생활 기록과 문서를 묶어 보는 로컬 POC입니다. 첫 화면은 `생활`이며 기존 `문서`와 `군집` 탭도 이용할 수 있습니다. 앱에는 인터넷 권한이 없습니다. 기록과 임베딩, 사용자가 입력한 평가 정보는 앱 전용 저장소에 보관하며 Android 자동 백업과 기기 이전 대상에서 제외합니다.

## 생활 기록 사용하기

1. `생활 기록`에서 메모를 작성하거나 `기존 문서 연결`로 문서 탭에 등록된 문서를 고릅니다. 다른 앱에서 텍스트를 공유하면 저장 전에 제목과 내용을 확인할 수 있습니다. 메모와 공유 글의 내용은 20,000자까지 저장하며 초과한 글을 임의로 자르지 않습니다.
2. `알림 수집 설정`에서 Android 알림 접근을 허용하고 수집할 앱을 선택한 뒤 수집을 켭니다. 기본 설정은 꺼짐입니다. 선택한 앱의 현재 알림과 이후 알림 중 기기가 전달한 텍스트를 수집합니다. 이미 사라진 알림이나 내용이 가려진 알림은 복원할 수 없습니다. 앱이 보이지 않으면 그 앱의 알림을 표시한 뒤 목록을 새로 고칩니다.
3. `주제와 주문`에서 기록 수와 내용을 확인합니다. 기록 상세에서 대표 주제를 옮기거나 추가 주제를 연결하고 주문을 옮기거나 분리할 수 있습니다. 자동으로 제안한 연결은 원문을 보고 확인합니다. 같은 기록이 여러 주제에 나타날 수 있지만 전체 기록 수는 중복 없이 셉니다.
4. `일정·할 일과 후보`에서 원문과 날짜를 확인하고 필요한 후보만 저장합니다. 날짜가 불명확하면 비워 두거나 직접 수정합니다. 일정과 할 일은 이 앱 안에만 저장되며 기기 캘린더나 알림을 만들지 않습니다.
5. 생활 화면의 검색에서 기록을 찾고 원문을 엽니다. 임베딩이 아직 준비되지 않은 글도 낱말로 찾을 수 있습니다. 처리 중이거나 실패한 기록이 있으면 자동 군집을 완성된 전체 결과로 보여 주지 않습니다. 실패한 처리는 `알림 수집 설정`에서 다시 시도할 수 있습니다.

알림은 같은 알림의 서로 다른 내용을 이력으로 남기며 각 이력은 수집한 시각부터 30일이 지나면 삭제 대상이 됩니다. 삭제 작업은 앱 사용 중 또는 백그라운드 작업이 실행될 때 처리되므로 기기 전원이나 Android의 작업 제한에 따라 지연될 수 있습니다. 기한이 지난 알림은 정리 전에도 목록·검색·군집에서 제외합니다. 알림 수집을 끄거나 앱 선택을 해제하면 이후 수집을 멈추고 기존 기록은 보관합니다. `수집한 알림 전체 삭제`로 기존 알림을 지울 수 있습니다. 사용자가 승인한 일정·할 일은 원문이 삭제되거나 만료되어도 남으며 원문이 없음을 표시합니다. 삭제는 앱 데이터의 논리적 삭제이며 저장 장치의 물리적 완전 삭제를 보장하지 않습니다.

기존 문서 연결은 앱에 등록된 문서를 참조합니다. 생활 화면에서 연결을 삭제해도 문서 기록과 기기의 원본 파일은 유지합니다. 반대로 문서 탭에서 문서 기록을 삭제하면 생활 기록의 연결도 사라집니다. 선택한 알림의 원본은 다른 앱에 그대로 두며 수정하거나 삭제하지 않습니다.

## 군집 비교와 7일 시험

`생활 군집 비교`의 가상 개발 자료와 평가 자료는 서로 다른 주문으로 구성됩니다. 각 자료에는 주문 카드가 20개 있습니다. 사람은 카드에 있는 세 기록이 실제로 같은 가상 주문인지, 표시된 주제가 어울리는지 확인합니다. 다른 카드의 주문은 서로 다릅니다. 문제가 있는 카드는 확인 표시를 하지 말고 자료를 수정해야 합니다.

개발 자료의 검토를 마치면 `개발 자료로 기준값 정하기`를 실행합니다. 모델 단독 결과를 기준으로 주제와 주문의 거리 기준을 각각 정합니다. 평가 자료도 모두 확인한 뒤 `두 방식 평가`를 누르면 모델 단독 방식과 주문번호·출처 단서를 결합한 방식의 정밀도·재현율·F1과 잘못 합친 쌍을 비교합니다. 관련·무관 쌍이 각각 50개 이상이어야 하며 F1 0.8은 각 방식의 목표이지 미리 확인된 결과가 아닙니다. 모델이나 기준이 바뀌면 이전 결과는 현재 결과와 구별됩니다. 검토와 평가를 실행하기 전의 판정은 미판정입니다.

실제 기록은 상세 화면에서 같은 주문에 같은 `평가용 정답 주문`을 입력한 항목만 별도로 비교합니다. 가상 자료의 점수와 합치지 않습니다. 정답이 있는 관련·무관 쌍이 각각 50개 미만이거나 개발 기준이 없으면 실제 기록의 수치는 참고용입니다. 자동 군집과 사용자가 직접 정정한 주제·주문은 따로 보관하므로 자동 방식 비교에 사용자 정정이 섞이지 않습니다.

개발 자료로 기준을 정한 뒤 `7일 사용 기록`에서 시험을 시작합니다. 7일 동안 기록 찾기, 일정·할 일, 알림 정리를 생활 POC와 평소 방식으로 각각 사용해 보고 성공 여부·소요 시간·불편을 남깁니다. 불편 사항에는 개인 원문을 적지 않습니다. 시험 중에는 개발 자료의 확인 상태와 기준값을 바꿀 수 없습니다. 7일 실사용 결과와 대상 기기의 속도·메모리 평가는 직접 시험하기 전까지 미판정입니다.

## 문서 군집 실험 안내

`문서` 탭에서 `기기 문서 스캔`을 누르면 앱이 공유 저장소를 검색합니다. 접근 권한이 있는 하위 폴더를 대상으로 삼습니다. 처음 실행할 때는 Android 설정에서 ‘모든 파일 접근’을 허용해야 합니다. 다른 앱의 비공개 파일과 클라우드에만 있는 문서는 검색하지 않습니다. 원본 파일은 옮기거나 수정하지 않습니다. 스캔 중에는 진행 상태를 확인하고 취소할 수 있습니다.

UTF-8 TXT·Markdown과 텍스트 PDF를 처리합니다. 스캔 PDF는 지원하지 않습니다. 10MB를 넘는 파일과 20,000자를 넘는 TXT·Markdown은 제외합니다. PDF는 50쪽 또는 추출한 글 100,000자를 넘으면 제외합니다. 읽지 못한 파일·폴더와 제한에 걸린 파일은 스캔 결과에 이유별로 표시합니다.

다시 스캔할 때 파일 크기와 수정 시각이 같으면 기존 임베딩을 재사용하고, 달라지면 다시 처리합니다. 정답 주제는 그대로 둡니다. 저장소 검색이 끝난 경우에만 사라진 자동 수집 문서를 앱 목록에서 정리합니다. 자동 수집 문서를 앱에서 삭제해도 기기에 있는 원본은 삭제하지 않습니다. `문서 가져오기`를 눌러 파일을 직접 선택할 수도 있습니다. 등록하기 전에 추출한 글을 확인하며 PDF 원본은 앱 내부에 복사합니다.

같은 주제의 문서에는 같은 정답 주제 이름을 입력합니다. 라벨을 비워 둔 문서는 군집에는 포함하지만 정량 지표 계산에서는 제외합니다.

`군집` 탭의 개요에는 전체 문서 수, 군집 수, 미분류 문서 수가 나옵니다. 군집 카드에는 문서 수와 제목 두 개를 미리 보여 줍니다. 카드를 누르면 해당 군집의 모든 문서가 목록에 나타납니다. 문서를 누르면 추출한 글 전체와 출처·정답 주제를 볼 수 있습니다. 문서가 하나인 결과는 `미분류` 항목에 모아 보여 줍니다. 지도에서 점을 눌러도 문서 상세 화면으로 이동합니다. 군집별 👍·👎 의견은 군집 상세에서 남깁니다. 미분류 의견은 문서별로 남깁니다.

2D PCA 지도는 두 손가락으로 확대하거나 이동할 수 있습니다. 거리 임계값은 0.00~2.00 범위에서 0.01씩 조절하며 기본값은 0.05입니다. 기준을 바꾸면 군집·문서 수·지표를 다시 계산합니다. 계산 중에는 이전 문서 수를 새 기준의 결과로 표시하지 않습니다.

정밀도·재현율·F1은 정답 라벨이 입력된 문서 쌍만으로 계산합니다. 라벨 비율과 평가에 사용한 문서 수도 함께 표시합니다. PCA 지도는 768차원 임베딩을 2차원으로 펼쳐 보여 줍니다. 점 사이의 거리를 군집 품질 점수로 해석하지 않습니다. 고정 평가 데이터와 기준값은 군집 실험과 분리해 유지합니다.

## 확인 순서

1. `문서` 화면에서 `기기 문서 스캔`을 누르고 필요한 접근 권한을 허용합니다.
2. 스캔 결과에서 처리한 문서와 제외한 문서의 수를 확인합니다.
3. `군집` 화면에서 군집별 문서 수를 확인합니다. 군집을 열어 문서 목록과 원문을 살펴보고 거리 임계값을 바꿔 봅니다.
4. 품질 지표가 필요하면 `문서` 화면에서 문서별 정답 주제를 입력합니다.

## 빌드

모델 변환 도구는 `poc/embedding/.venv`의 Python 환경과 로컬 학습 어댑터를 사용합니다. 고정 평가 자료와 모델을 만든 뒤 Android 폴더에서 APK를 빌드합니다.

```bash
python3 poc/android/tools/package_eval_data.py
PYTHONPATH=poc/embedding poc/embedding/.venv/bin/python poc/android/tools/export_embedding_model.py --precision int8_embedding
cd poc/android
./gradlew assembleDebug
```

APK 위치:

```text
poc/android/app/build/outputs/apk/debug/app-debug.apk
```

APK에는 ONNX 모델과 토크나이저가 포함됩니다. 모델 파일은 크기 때문에 Git에서 제외합니다. 앱은 ONNX Runtime CPU를 사용해 비행기 모드에서 실행하며, 모델 파일과 토크나이저의 SHA-256, 기준 모델 revision, 선택된 어댑터 checkpoint를 확인합니다. 검증된 학습 모델을 불러오지 못하면 기본 모델로 대체하지 않습니다.

LiteRT 변환본은 기준 임베딩과 일치하지 않아 사용하지 않습니다. Android용 ONNX Runtime CPU 모델은 행별 int8 토큰 임베딩과 float32 Transformer로 내보냈고, Python ONNX Runtime에서 패딩·동적 길이 입력 모두 기준 임베딩과 코사인 유사도 0.999 이상인지 확인했습니다. ONNX 모델과 토크나이저를 비공개 Hub 저장소 revision `dbb3bdd252f9034681cb65efee5d7f4b8cbef7bf`에 올렸고, artifact revision과 파일 해시를 기록한 최신 저장소 revision은 `526a59e58e244680fd076a58e646cdd3f4efd1bc`입니다. 앱 manifest에는 소스 모델·artifact revision과 파일 해시를 기록합니다.

## 확인하지 않은 항목

실제 사용자 알림의 수집 범위와 기종별 백그라운드 제한, 오프라인 실사용, CPU 지연, 추가 PSS, Android 백업·이전 동작은 대상 실기기에서 별도로 확인해야 합니다. POC의 품질과 7일 실사용 판정은 자료 검토와 시험 전까지 미판정입니다.
