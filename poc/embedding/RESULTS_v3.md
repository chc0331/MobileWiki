# 사건 맥락·군집 개선 v3 실험 기록

기록일: 2026-10-31 · 상태: **새 v3 학습·개발 선택과 시험 자료 생성·자동 검증·잠정 시험 평가 완료, 의미·사람 검수 전**. 시험 지표는 품질 검토 전 잠정 진단이다.

같은 v2 모델에 군집 후처리를 적용하자 전체 사건 쌍 F1은 0.348에서 0.455로 올랐다. 원문과 평가 정답을 고정한 재학습 실험에서도 같은 이름 가리기 조건의 전체 F1이 0.355에서 0.404로 올랐다. 다만 표본 문서 쌍 F1과 이전 v1 자료의 검색 성능은 하락했다. 새 v3 모델은 개발 자료에서 검색 Recall@5 0.933, 전체 사건 쌍 F1 1.000을 기록했으나 이전 v1·v2 자료의 회귀 점수는 낮았다. 잠정 시험 평가에서 LoRA 모델의 Recall@5는 0.840, 전체 사건 쌍 F1은 0.832였다. 기반 모델은 각각 0.872와 0.483이었다. 검색 목표는 달성하지 못했고 군집 목표는 넘었지만 `test-0010` 의미 오류와 사람 검수 미완료 때문에 결과를 최종 판정으로 보지 않는다.

## 평가 지표와 기존 자료의 문제

v2 학습 모델은 같은 인물의 다른 사건을 분리했지만 같은 주제·날짜인 다른 가족 사건을 많이 합쳤다. 시험 메모 1,000개에서 발생한 오결합 4,203쌍은 모두 이 조건에 해당했다. 기존 문서 쌍 표본에는 이 충돌이 충분히 반영되지 않았다. 이 진단은 합성 자료에 대한 것이며 실제 사용자 메모에서도 같은 원인이 지배적인지는 확인하지 않았다.

Recall@1·Recall@5는 질문 140개 중 정답 메모가 검색 결과 상위 1개·5개에 포함된 비율이다. MRR은 정답 순위의 역수를 평균한 값이다. 정답이 1위이면 1, 2위이면 0.5로 계산한다.

전체 사건 쌍 평가는 시험 메모 1,000개에서 만들 수 있는 모든 문서 쌍 499,500개를 비교한다. 이 중 실제로 같은 사건에 속한 쌍은 1,500개다. 정밀도는 같은 묶음에 넣은 쌍 중 맞는 비율이고 재현율은 실제 같은 사건 쌍 중 찾아낸 비율이다. F1은 두 비율의 조화평균으로, `2 × 정밀도 × 재현율 ÷ (정밀도 + 재현율)`로 계산한다. 표본 문서 쌍 F1은 별도로 고른 100쌍의 결과이므로 전체 평가와 구분한다.

오결합은 다른 사건의 메모를 같은 묶음에 넣은 쌍이다. 놓친 관련 쌍은 같은 사건의 메모를 서로 다른 묶음으로 나눈 쌍이다. 한 지표만 보면 과도하게 합치거나 나누는 오류를 놓칠 수 있어 두 수와 정밀도·재현율을 함께 기록한다.

## 1단계: 같은 v2 모델의 군집 후처리

학습 가중치와 검색 입력은 유지하고 군집 방법만 비교했다. 메모를 나타내는 숫자 목록인 임베딩 벡터에서 평균과 주성분을 계산할 때는 학습 문서만 사용했다. 군집 설정은 개발 자료에서 고른 뒤 시험 자료에 그대로 적용했다.

선택한 방법은 상위 주성분 세 개를 제거하는 ABTT, complete 연결, 거리 기준값 0.49다. ABTT는 여러 문서에서 공통으로 강하게 나타나는 벡터 방향을 빼는 보정이다. complete 연결은 두 묶음 사이에서 가장 먼 문서 쌍의 거리를 합침 판단에 사용한다. 서로의 가까운 이웃 다섯 개에 포함되지 않은 문서 쌍에는 거리 0.15를 더한다. 날짜 페널티와 추가 재분할은 선택되지 않았다.

| --- | ---: | ---: |
| 검색 Recall@5 | 93/140 (66.4%) | 93/140 (66.4%) |
| 검색 MRR | 0.513 | 0.513 |

오결합은 줄었지만 같은 사건을 나누는 오류가 늘었다. 개발 자료의 전체 사건 쌍 F1은 0.808이었고 시험 자료에서는 0.455였다. 개발 점수를 시험 성능으로 대신할 수 없다. 검색 Recall@5 0.90과 전체 사건 쌍 F1 0.80이라는 두 목표를 충족하지 못했다.

문자 TF-IDF 기준선도 실행했다. 이 방법은 2~5글자 조각의 빈도로 문서를 나타낸다. 어휘와 가중치는 학습 문서에서만 계산하고 개발 자료에서 설정을 골랐다. 시험 전체 사건 쌍 F1은 0.084, 오결합은 4,782쌍이었다. 문자 조각의 겹침으로 얼마나 묶이는지 비교할 기준이다.

실제 평가 파일은 `artifacts/context-hardneg-v3/phase1_v2/tuned.json`이다. 선택한 설정과 학습 보정 통계는 같은 위치의 `tuned.cluster_profile.json`, `tuned.cluster_profile.npz`에 있다.

## 2단계: 원문과 정답을 고정한 v2 재학습

새 자료 생성과 분리해 변경 효과를 확인하는 통제 실험을 마쳤다. 파생 자료 버전(revision)은 `shortcut-hardneg-v2-cluster-phase2`다. 원래 v2의 문서·질문·평가 문서 쌍·검수표 파일을 그대로 복사하고 학습용 관계만 바꿨다. 이 절의 `phase2_v2/` 경로는 `artifacts/context-hardneg-v3/` 아래에 있다. 파일 내용이 같은지 확인하는 해시(SHA-256)도 원본과 일치한다. 이 결과는 새 `context-hardneg-v3` 텍스트에서 측정한 성능이 아니다.

학습 예시는 기준 입력·관련 메모·오답 메모를 한 묶음으로 만든다. 검색용 400개와 군집용 800개를 사용했다. 군집 오답은 같은 가족의 다른 사건 A 400개, 같은 주제의 다른 가족·다른 정답값 B 240개, 같은 정답값의 다른 가족 사건 C 160개다. C는 두 메모 본문에 같은 정답값이 실제로 포함된 경우를 사용했다. 어려운 오답 선별에는 학습 문서만 사용했다.

군집 입력에서는 메타데이터로 알고 있는 가상 인물 이름만 가렸다. 보관한 원문과 검색 입력은 유지했다. 이 조건은 실제 메모에서 이름을 자동으로 찾아 가리는 성능을 뜻하지 않는다. 기준 모델·이전 v2 모델·새 학습 모델과 문자 기준선에 같은 군집 입력 정책을 적용했다.

### 개발 자료의 네 후보 선택

기반 모델 버전은 `f9972ac22e696a105c482202646979e33e4b5a1e`로 고정했다. 기반 모델 일부에 작은 학습 값을 덧붙이는 LoRA 어댑터를 네 조건으로 학습했다. q/v·q/k/v/o는 문장 안의 정보 관계를 계산하는 attention 부분에서 학습할 대상을 가리킨다. 마진은 군집 학습에서 관련 메모와 오답의 거리 차이를 벌리도록 두는 값이다.

모든 후보를 2 epoch, 총 300단계 학습했다. epoch는 전체 학습 예시를 한 번 사용하는 단위다. 개발 검색 Recall@5가 0.90 이상인 후보에서 전체 사건 쌍 F1, 오결합 수, MRR 순서로 선택했다. 아래 체크포인트는 학습 중 저장한 가중치에서 개발 자료로 고른 시점이다.

| 학습 후보 | 선택 체크포인트 | 개발 Recall@5 | 개발 전체 사건 쌍 F1 |
| --- | ---: | ---: | ---: |
| q/v, 마진 0.1 | 150 | 0.9067 | 0.8008 |
| q/k/v/o, 마진 0.1 | 150 | 0.9067 | 0.7986 |
| q/k/v/o, 마진 0.2 | 300 | 0.9200 | 0.8200 |

선택한 후보는 `qkvo-margin-02`, 체크포인트 300이다. 군집은 complete 연결과 거리 기준값 0.35를 사용한다. 본문에서 확정한 두 날짜가 7일 넘게 떨어지면 거리 0.3을 더한다. 서로의 가까운 이웃 다섯 개에 포함되지 않은 쌍에는 거리 0.15를 더한다. 벡터 보정과 추가 재분할은 선택되지 않았다.

각 모델의 후처리 설정은 개발 자료에서 따로 골랐다. 이 비교는 학습과 후처리를 합친 전체 처리 과정의 비교다. 가중치 변경만의 효과를 분리한 비교로 해석하지 않는다. 1단계의 이름 유지 조건에서 얻은 전체 F1 0.455도 새 모델의 0.404보다 높다. 두 비교에서는 군집 입력 정책과 학습 가중치가 모두 달라졌다. 두 점수의 차이를 한 변경의 효과로 해석하지 않는다.

같은 이름 가리기 정책의 문자 TF-IDF 기준선은 시험 전체 F1 0.101, 오결합 2,599쌍이었다. 새 학습 모델도 검색 Recall@5 0.90·전체 사건 쌍 F1 0.80 목표에 미달했다. 표본 F1 역시 PRD 기준 0.80에 미달했다.

실제 결과는 `artifacts/context-hardneg-v3/phase2_v2/training/evaluation/`의 `base.json`, `base_hybrid.json`, `tuned.json`에 있다. 같은 입력 정책의 이전 모델 결과는 `phase2_v2/comparisons/old_v2_masked_hybrid.json`이다. 전체 실행 기록은 `phase2_v2/run.json`, 별도 대조 기록은 `phase2_v2/report_facts.json`에 있다. 별도 대조에서는 44개 검사를 통과했고 고정 파일 63개와 추가 산출물 52개의 해시를 확인했다.

## 3단계: 새 v3 자료 생성과 학습 진행

새 자료 버전은 `context-hardneg-v3`다. 네 메모가 구체적인 상황과 목적을 공유하게 한다. 각 분할의 사건 60%는 같은 날짜·주제의 서로 다른 5가족 사건으로 배치한다. 상황과 목적의 개별 빈도는 고르게 맞추며 두 요소의 조합은 학습·개발·시험 사이에서 겹치지 않게 한다.

정답 메모 한 개를 먼저 생성한다. 주변 메모 세 개와 질문은 각각 독립 요청으로 만든다. 이 네 요청에는 정답값·정답 단서·정답 메모의 응답을 전달하지 않는다. 상황과 목적은 동의 표현 후보를 허용한다. 정답 문장을 옮기거나 파이썬으로 사실을 삽입하지 않는다.

생성 교사는 `qwen3.5:9b-q4_K_M`이며 모델 해시는 `56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90`이다. 생성 규칙은 `qwen-event-v3-blind-context-r12`로 기록한다. 한 독립 요청이 여덟 번 실패하면 해당 실행을 중단한다. 복구에는 새 난수 공간을 쓰고 검증을 통과한 독립 요청만 재사용한다. 실패 응답과 소요 시간도 보존한다.

### 생성 실패 복구와 남은 자료 품질

`train-0127`의 정답 메모 요청은 기존 방식에서 세 난수 공간에 걸쳐 24번 실패했다. 같은 요청의 직전 실패 원시 응답만 수정 초안으로 전달하는 실패 안내 버전 4를 추가했다. UTF-8로 저장한 원시 응답의 해시를 확인한 뒤 그 안의 응답 본문만 JSON 문자열로 인용한다. 교사가 카드의 사실을 기준으로 새 응답을 작성한다. 버전 1·2·3의 프롬프트와 해시는 보존했으며 39,375개 프롬프트의 바이트 일치를 검사했다.

버전 4는 정답 메모의 자기 실패 초안에만 적용한다. 주변 메모 세 개와 질문은 기존 버전 3 요청을 유지하며 정답·초안·이력을 받지 않는다. 이 요청들은 각각 새 대화의 두 메시지로 실행한다. 별도 진단에서 시험한 단일 초안 응답은 자료에 넣지 않았다. 실제 복구 결과와 구분해 보관한다.

10개 범주의 생성 표본을 AI가 보조 검토했다. `train-0106`의 연락 목적 연결 오류와 `train-0126`의 길 안내 역할 반전은 해당 독립 요청만 재생성한 뒤 다시 대조했다. 복구한 `train-0127`의 주변 메모에서는 냉각수 보충 외에 엔진 오일 확인이라는 경쟁 정답을 발견했다. 기존 검사가 엔진오일과 엔진 오일의 띄어쓰기 차이를 놓친 경우였다.

알려진 정답 후보는 띄어쓰기 차이도 비교하도록 검사를 보완했다. 비교용 문자열만 사용하며 저장한 원문을 고치지 않는다. 지정된 정답값의 정확한 포함 조건도 유지했다. 근거 구절은 기존 날짜 형식 정규화 후 본문과 일치하는지 확인한다. 띄어쓰기 검사가 반려한 주변 메모 한 개만 다시 생성했고 다른 네 출력은 보존했다.

전체 생성을 재개하기 직전에는 128개 사건, 메모 512개가 있었다. 정해진 자동 검사와 질문 중복 검사를 통과했다. 마지막 AI 보조 검토도 핵심 정답 관계를 기준으로 잠정 재개를 허용했다. 다만 정비할 정확한 항목인 ‘정비 항목’ 같은 인위적인 표현과 대상 차량이 생략된 수혜자 표현이 남았다. 이 판정은 128개 전체와 이후 자료의 의미 검수가 완료됐다는 뜻이 아니다.

가상 인물 이름을 직접 쓴 학습 사건 100개의 정답 메모에는 모두 전체 이름이 있다. 같은 사건의 비정답 메모 300개 중 209개에도 이름이 있다. 검색 질문 100개에도 전체 이름이 있어 이름 맞추기 지름길이 남아 있다. 군집 입력에서는 알려진 가상 이름을 가리지만 검색 입력에는 이 가리기를 적용하지 않는다.

이 단계의 사건 검토 기록은 `artifacts/context-hardneg-v3/debug/semantic-gate-275.json`에 있다. 모델 선택과 회귀 결과는 같은 디렉터리의 `staged_run.json`, `training/experiment.json`, `regression_v1/tuned.json`, `regression_v2/tuned.json`에 보존했다. 새 v3 시험 사건 250개는 생성과 자동 검증을 마쳤다. 당시에는 의미 검토와 사람 검수가 남아 있어 시험 평가를 보류했다.

### 시험 자료 생성의 예외와 잠정 검토

`test-0012`는 정답 메모 요청이 기존 공간 한 곳과 일반 복구 공간 두 곳에서 각각 8회씩 실패해 생성이 멈췄다. 실패 24건의 응답·오류·소요 시간은 보존했다. 사용자 승인으로 누적 실행 한도를 24시간에서 32시간으로 늘린 뒤, 이 사건에만 새 난수 공간 3000을 한 번 추가했다. 이 공간의 5회차에서 정답 메모가 통과했고 주변 메모와 질문도 생성했다. 이후 사건에는 일반 복구 한도인 새 공간 두 개를 그대로 적용한다. 추가 공간은 원래 생성 규칙의 예외이므로 시험 결과를 해석할 때 별도로 밝힌다.

초반 시험 사건 13개를 AI가 잠정 대조했다. 핵심 정답 관계 10개는 통과, 2개는 불확실, `test-0010` 질문 1개는 오후 약속과 야간 별자리 구경의 순서를 반대로 읽히게 해 수정이 필요하다. 이 표본은 시험 전체의 품질 판정이 아니다. 생성·검토·예외 기록은 `artifacts/context-hardneg-v3/debug/test-early-semantic-notes.json`, `debug/test0012-one-time-exception.json`, `staged_run.json`에 있다. 이 시점에는 새 v3 시험 지표를 계산하지 않았다.

### 시험 자료 생성 완료와 자동 검증

`test-0137`에서 기존 요청 문구가 반복 실패했다. 버전 5의 보충 안내로 정답 메모는 통과했지만, 주변 메모가 입력의 지시 표현을 본문에 옮겼다. 이후 버전 6은 카드의 상황·목적과 날짜·이름 규칙을 짧게 전달했다. 주변 메모와 질문에는 정답값이나 정답 메모를 전달하지 않았다. 교사 모델과 검증 규칙은 바꾸지 않았고, 이전 응답과 실패 횟수·시간 장부를 보존했다.

전체 525개 사건(학습 200개, 개발 75개, 시험 250개)을 생성했다. 메모는 2,100개, 질문은 525개다. 개별 사건 검사, 질문 중복 검사, 사건 간 중복 메모 검사를 통과했다. 기존 412개 사건의 원본 바이트는 그대로이고, 학습·개발 자료와 고정한 모델 선택도 유지했다.

완성 자료를 별도 검증 폴더에서 가공해 전체 자료 검사를 실행했다. 학습·개발·시험 메모 800·300·1,000개, 질문 525개, 평가 쌍 200개, 학습용 세 문서 묶음 1,200개가 모두 검증을 통과했다. 검증 폴더의 학습·개발 자료는 앞서 고정한 자료와 일치한다. 결과는 `artifacts/context-hardneg-v3/completion_resume/summary.json`과 `validation.json`에 있다.

자동 검사는 문장의 뜻이나 정답의 유일성을 끝까지 판정하지 않는다. 앞서 발견한 `test-0010` 질문의 시간 순서 오류도 아직 수정되지 않았다. 시험 자료 전체의 의미 검토와 사람 검수는 남아 있다. `awaiting_test_semantic_audit` 단계에서 2026-10-31 사용자 요청으로 잠정 평가를 실행했다. 이 평가는 검수 절차를 완료한 판정이 아니다.

### v3 시험 평가 결과 (잠정)

학습·개발 자료와 선택 설정은 그대로 유지했다. 기존 140개 제한을 없애 시험 질문 250개 전체를 평가했다. 미세 조정 모델에는 개발 자료에서 선택한 체크포인트와 고정 군집 프로필을 적용했다. 기반 모델은 같은 학습·개발 분할에서 별도 군집 프로필을 선택한 뒤 시험 자료에 적용했다. 두 모델 모두 시험 자료를 모델 선택이나 기준값 설정에 사용하지 않았다.

| 시험 지표 | 기반 모델 | v3 LoRA 모델 |
| --- | ---: | ---: |
| 검색 Recall@5 | 0.872 (218/250개 질문) | 0.840 (210/250개 질문) |
| 검색 MRR | 0.488 | 0.654 |
| 문서 쌍 표본 F1 | 0.649 | 0.943 |
| 전체 사건 쌍 정밀도 | 0.440 | 0.718 |
| 전체 사건 쌍 재현율 | 0.535 | 0.990 |
| 전체 사건 쌍 F1 | 0.483 | 0.832 |

v3 LoRA 모델은 전체 사건 쌍 F1 목표인 0.80을 넘겼다. 검색 Recall@5는 목표인 0.90에 미치지 못했다. 전체 사건 쌍 F1과 MRR은 기반 모델보다 높았다. 검색 Recall@5에서 정답을 찾은 질문은 기반 모델보다 8개 적었다. 시험 쌍 100개의 F1은 0.943이었으며, 전체 사건 쌍 결과와 구분해 해석해야 한다. 이 평가는 사람 검수 전 자동 정답에 따른 잠정 진단이다.

평가 출력은 `artifacts/context-hardneg-v3/evaluation/v3-test-diagnostic.json`과 `base-v3-test-diagnostic.json`에 있다. 두 리포트는 각각 미세 조정 모델의 개발 선택 프로필과 기반 모델의 개발 분할 선택 프로필을 사용했다. `test-0010`의 시간 순서 오류가 있고 시험 자료 전체의 의미 검수와 사람 검수도 끝나지 않았다. 이 점수는 공식 품질 판정이나 배포 승인 근거로 사용할 수 없다.

### 실제 학습 실행 계획과 예산

네 학습 후보의 비교는 2단계의 고정 v2 자료에서 완료했다. 새 v3 실행은 남은 자료 생성·평가 시간을 확보하도록 그 개발 선택에서 고른 q/k/v/o·마진 0.2 설정 한 개를 사용한다. 이 실행 계획을 `p2-transfer`로 기록했다. 가중치는 고정된 기반 모델에서 새로 학습한다. 체크포인트와 군집 설정은 v3 개발 자료에서 고른 뒤 시험 자료에 적용한다. 새 v3 자료에서 네 후보를 모두 학습했다고 표시하지 않는다.

원래 네 후보 실행 계획은 `artifacts/context-hardneg-v3/run_staged.before_phase2_transfer.json`에 보존했다. 현재 선언과 근거는 `run_staged.phase2_transfer_implementation.json`에 있다. 학습·개발 자료를 먼저 완성하고 선택을 고정한 뒤 시험 자료를 생성한다. 시험 점수를 보고 모델이나 설정을 다시 고르지 않는다.

처음에는 생성·어려운 오답 선별·학습·개발 선택·평가·시각화를 합계 24시간 예산으로 관리했다. 시험 자료 생성 중 사용자 승인을 받아 누적 한도를 32시간으로 늘렸다. 기존 생성 장부와 별도 작업 장부에 2단계의 오답 선별·실험 시간을 더하며 새 v3 비용도 계속 누적한다. 실험 기록의 전체 누적값에 이미 포함된 생성 시간을 다시 더하지 않는다.

정밀 타이머를 붙이기 전의 1단계 작업에는 보수적으로 3,600초를 배정했다. 이 배정값은 실측 시간과 구분해 예산에서 차감한다. 128개 사건에서 전체 생성을 재개한 시점의 보수적 누계는 약 9.566시간이었다. 시간 한도에 도달하면 미완료 자료와 미측정 결과를 그대로 기록한다. 새 v3 시험 지표는 산출했지만 사람 검수 전 잠정 진단으로 남아 있다.

## 군집 탐색 환경과 검증 범위

로컬 화면은 `http://127.0.0.1:8501`에서 실행한다. 실행법은 [실행 안내](README.md)의 「로컬 군집 탐색 화면」에 있다. 기존 v2·1단계 후처리·2단계 모델과 회귀 결과를 담은 8개 시각화 캐시를 확인했다. 2단계 모델의 지표, 오류 원문, 1단계 모델과의 비교, 지도 PNG 다운로드도 실제 화면에서 확인했다.

지도에서 점이나 영역을 선택하면 원문과 예측 묶음을 확인한다. 오결합·과분할 화면에서는 두 메모를 나란히 읽는다. 모델 비교에서는 같은 자료의 같은 문서를 함께 선택해 묶음 구성이 어떻게 달라졌는지 확인한다. 개발 실험은 메모리의 개발 결과만 바꾸며 시험 결과는 고정한다.

PCA·t-SNE는 여러 숫자로 된 벡터를 2차원 점으로 펼쳐 보는 도구다. 지도는 원문을 찾아보기 위한 것이며 화면상 거리나 모델 사이의 점 이동량을 품질 점수로 해석하지 않는다. 군집은 원래 임베딩 공간의 거리로 만든다. 지표는 예측 묶음과 정답 사건 쌍을 비교해 계산한다. 히트맵은 실제 군집 거리와 원본 코사인 거리를 선택해 본다.

CPU 통합 검사에는 공개 `tests/`와 기존 로컬 운영 검증 5개를 함께 지정했다. 검사 293개가 통과했다. 이 검사는 코드와 정해진 불변 조건을 확인한다. 생성된 문장의 자연성이나 사람 검수를 대신하지 않는다.

새 시험 자료의 검색 질문 140개와 문서 쌍 100개, 태그 표본 최대 30개는 사람 검수가 필요하다. 실제 사용자 메모의 품질도 확인하지 않았다. Android 모델 변환·APK·실제 기기 성능·7일 사용 평가는 이 실험 결과에 포함하지 않는다.
