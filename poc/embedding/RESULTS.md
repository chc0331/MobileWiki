# EmbeddingGemma 2 한국어 메모 실험 결과

기록일: 2026-10-28 · 상태: **잠정 결과**. 평가 정답의 사람 검수와 Hugging Face Hub 업로드는 완료되지 않았다.

## 이번에 확인한 범위

M2 Mac에서 텍스트 전용 `google/embeddinggemma-2`에 작은 추가 가중치인 LoRA를 학습했다. 목표는 한국어 생활 메모에서 근거 문서를 찾고 같은 사건의 문서를 묶는 것이다. PC에서 검색과 묶음 결과를 측정하고 묶음 이름은 사람 검토용 표로 뽑았다. Android 실행, 저장 공간, 메모리, 속도와 생성형 답변은 시험하지 않았다.

## 데이터와 실행 기록

로컬 `qwen3:8b`가 가상 가족의 10가지 생활 주제로 사건 525개를 만들었다. 사건마다 메모 4개가 있어 원문은 2,100건이다. 가족과 사건을 나눠 학습 800건, 개발 300건, 고정 평가 1,000건으로 배치했다. 학습에는 검색용 200개와 묶음용 800개의 세 쌍 예시를 썼다. 고정 평가에는 검색 질문 140개와 문서 쌍 100개를 썼다. 질문 140개 중 70개는 원문과 다른 표현으로 만든 문장이다.

생성 단계의 자동 보정 기록은 2,244건이다. 정답을 짐작하게 하는 낱말을 지우는 후속 정리 기록은 244건이며, 그중 답 단서가 든 문장 제거는 148건이다. 서로 다른 사건에 같은 메모 문장이 나온 8개 사건은 다시 생성했다. 전체 자료의 문서 중복, 가족·사건 분할, 답 근거, 파일 해시 검사가 통과했다. 연락처·주민번호·이메일 형태는 생성 기록과 재생성 이력에서 검출되지 않았다. 교사 모델의 보정 전 응답 전문은 저장하지 않았다.

교사 모델 digest는 `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`이다. 기반 임베딩 모델 revision은 `914f7f89142e33e77833254d9c9b90c3cef7303b`다. LoRA는 524,288개 가중치를 2회차, 총 250단계 학습했다. 개발 자료의 문서 쌍 F1과 검색 평균 역순위(MRR)를 함께 비교해 2회차 체크포인트를 골랐다. 생성·중복 복구에 약 6.17시간, 학습에 약 9분이 들었다. 첫 복구 실패 시도의 약 150초는 생성 시간에 보수적으로 더했다. 두 작업의 합계는 약 6.32시간이다.

## 고정 평가 결과

검색은 1,000개 평가 메모에서 필요한 첫 근거 메모를 찾는다. Recall@5는 정답이 상위 5개 안에 있는 비율이고, Recall@1은 첫 결과가 정답인 비율이다. MRR은 정답의 순위가 앞설수록 커지는 값이다. 묶음의 F1은 잘못 묶은 문서 쌍과 놓친 문서 쌍을 함께 반영한 점수다. 모든 수치는 사람 검수 전 **잠정치**다.

| 지표 | 원본 모델 | 학습 모델 | 읽는 법 |
| --- | ---: | ---: | --- |
| 검색 Recall@1 | 53/140 (37.9%) | 113/140 (80.7%) | 첫 결과가 근거 메모인 질문 |
| 검색 Recall@5 | 112/140 (80.0%) | 134/140 (95.7%) | 상위 5개 안에 근거가 있는 질문 |
| 검색 MRR | 0.558 | 0.877 | 정답을 앞쪽에 놓는 정도 |
| 문서 쌍 100개 F1 | 0.667 | 0.990 | 평가 표본의 관련·무관 묶음 판정 |
| 전체 사건의 모든 문서 쌍 F1 | 0.006 | 0.529 | 생성 사건 ID로 전체 묶음의 과합침까지 검사한 자동 진단 |

낱말 검색 기준선은 Recall@1 19/140(13.6%), Recall@5 59/140(42.1%)였다. 인물 이름과 ‘첫 메모가 정답’이라는 위치만 이용한 규칙은 Recall@1 28/140(20.0%), Recall@5 140/140(100%)였다. 따라서 학습 모델의 Recall@5가 목표 90%를 넘었다는 사실만으로 의미 검색이 충분하다고 볼 수 없다. 첫 결과 적중률이 두 기준선보다 높아진 점은 긍정적이다.

묶음 평가 표본 100개에서는 학습 모델이 관련 문서 49쌍을 맞혔고 1쌍을 놓쳤다. 그러나 전체 1,000개 메모의 사건 ID로 모든 쌍을 대조하면, 서로 다른 사건을 같은 묶음에 넣은 쌍이 2,624개다. 정밀도는 모델이 함께 묶은 쌍 중 실제 같은 사건인 비율로, 0.361이다. 재현율은 실제 같은 사건인 쌍 중 모델이 함께 묶은 비율로, 0.989다. 두 비율을 함께 반영한 F1은 0.529다. 이 자동 진단의 모든 정답을 사람이 확인한 것은 아니지만, 표본 F1만으로 묶음 품질을 통과 처리하기 어려운 근거다.

학습 모델은 250개 사건을 132개 묶음으로 나눴다. 공통 낱말이 부족한 31개 묶음은 ‘이름 미정’으로 남겼다. 묶음 30개의 태그와 예시 메모를 별도 검수표에 담았다. 태그가 내용을 잘 설명하는지는 아직 사람이 확인하지 않았다.

## 판정과 남은 일

이 실험에서 검색은 합성 자료 기준으로 개선됐다. 문서 쌍 100개의 F1은 목표 0.80을 넘었지만, 전체 사건 쌍의 F1은 0.529였다. 서로 다른 사건을 한 묶음으로 합치는 문제가 커서 묶음 품질 목표 달성을 확인하지 못했다. 가상 인물 이름이 질문에 항상 들어가고 정답이 첫 메모에만 있는 자료 구조도 검색 점수를 높일 수 있다. 문장 자연스러움과 정답은 사람 검수 전이다. 따라서 임베딩 하위 POC의 최종 합격은 보류하고, 앱 전체의 가능·조건부 가능·불가능 판정은 하지 않는다.

다음에는 검색 질문 140개와 문서 쌍 100개의 원문·정답을 사람이 대조해야 한다. 태그 표본 30개도 별도로 확인한다. 잘못된 항목은 사건 원본을 고치고 새 평가 자료로 다시 검증한다. 묶음 기준과 학습 예시는 개발 자료의 **전체 사건 쌍**으로 개선한 뒤, 답이 늘 첫 메모에 있지 않은 새로운 평가 자료에서 시험해야 한다. 검수 전에는 비공개 Hugging Face Hub에도 자료와 어댑터를 올리지 않는다.

## 로컬 산출물

실행 파일과 데이터는 `poc/embedding/artifacts/`에 있으며 Git에는 포함되지 않는다. `dataset/manifest.json`은 교사·코드·파일 해시와 검수 상태를 담는다. `trained/training.json`에는 기반 모델 revision과 학습 설정이 있다. `evaluation/base.json`과 `evaluation/tuned.json`은 같은 데이터로 측정한 상세 점수다. `review140_dataset/review.csv`는 사람 정답 검수용 240행이고, `evaluation/tuned.tag_review.csv`는 태그 검토용 30행이다. 앞 검수표의 `accepted`와 `comment`를 내용이 같은 `dataset/review.csv`로 옮긴 뒤 `review.py`를 적용해야 Hub 업로드가 가능하다. 태그 검토는 별도 품질 판단에 사용한다.
