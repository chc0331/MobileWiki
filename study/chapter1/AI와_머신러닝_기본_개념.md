# 과목 1 AI와 머신러닝 기본 개념

이 자료는 AI를 처음 공부하는 비전공자를 위한 자료입니다. 문서 분류·군집화·요약을 예로 들어 AI와 머신러닝의 관계, 모델·학습·추론의 기본 원리를 익힙니다.

종이와 메모장만으로 필수 실습을 할 수 있습니다. 마지막의 Python 실습은 선택 사항이며, 별도 라이브러리나 GPU가 필요하지 않습니다.

전체 학습 순서는 [학습 계획서](../README.md)에서 확인할 수 있습니다.

## 1. 이 과목에서 할 수 있게 될 일

이 과목의 목표는 용어 암기보다 다음 질문에 자신의 말로 답하는 것입니다.

- 모델·데이터·파라미터는 각각 무엇인가요?
- 학습과 추론은 어떻게 다른가요?
- 정답으로 배우는 분류와 정답 없이 묶는 군집화는 어떻게 다른가요?
- N개 그룹의 N과 그룹 번호는 각각 무엇을 뜻하나요?
- 문서 군집화와 두 가지 요약 방식은 어떻게 다른가요?
- 정답 기준이나 ‘비슷하다’는 기준이 모호하면 어떤 문제가 생기나요?
- 사전학습·추가학습·추론은 어떻게 다른가요?
- 학습·검증·최종 평가 자료는 왜 구분하나요?

2~6절을 읽고 7~9절을 실습하세요. 10절의 문제를 푼 뒤 11절 해설과 비교합니다. Python 실행은 12절의 선택 실습에서 다룹니다.

## 3. AI와 머신러닝과 딥러닝

### 3.1 세 용어의 관계

**AI는 넓은 분야의 이름이고, 머신러닝은 그 안의 한 접근법이며, 딥러닝은 머신러닝의 한 종류입니다.**

| 용어 | 쉽게 이해하기 | 문서 분석에서의 예 |
| --- | --- | --- |
| AI 인공지능 | 판단·인식·언어 처리 같은 일을 컴퓨터로 수행하게 하는 넓은 분야 | 문서 내용을 분석하는 기능 |
| ML 머신러닝 | 데이터에서 예측이나 패턴 탐색에 쓸 계산 기준을 얻는 방법 | 라벨로 문서 분류를 배우거나 비슷한 문서끼리 묶기 |
| DL 딥러닝 | 여러 층으로 구성된 신경망을 학습하는 머신러닝 방식 | 사전학습 언어모델을 이용한 분류나 생성형 요약 |

![AI 안에 머신러닝이 있고 머신러닝 안에 딥러닝이 포함되는 관계](assets/ai_ml_dl.png)

*그림 2. AI, 머신러닝, 딥러닝의 포함 관계. 딥러닝은 AI를 구현하는 여러 방법 중 하나입니다.*

신경망은 입력 숫자를 여러 계산 단계에 통과시켜 결과를 내는 모델입니다. 각 단계인 ‘층’은 앞 단계의 숫자를 계산해 다음 단계로 넘깁니다. 학습에서는 이 계산에 쓰는 숫자를 조정합니다. 뇌가 문장을 이해하는 과정을 그대로 재현한다는 뜻은 아닙니다. 실제 계산과 학습 원리는 Chapter 4에서 배웁니다.

표의 ‘사전학습 모델’은 많은 자료로 미리 학습해 둔 모델을 뜻합니다. 이를 내 작업에 활용하는 방법은 5.4절에서 비교합니다. 모든 문서 분류 문제에 큰 언어모델이 필요한 것은 아닙니다. 작은 머신러닝 모델도 분류에 사용할 수 있습니다.

### 3.2 사람이 규칙을 쓰는 방법과 데이터로 배우는 방법

개발자가 다음 규칙을 직접 만들 수 있습니다.

> 문서에 ‘축구’라는 글자가 있으면 스포츠로 분류한다.

이 규칙은 이해하고 수정하기 쉽습니다. 하지만 ‘축구 경기 기록을 관리하는 새 앱의 기능 소개’도 스포츠로 분류할 수 있습니다. 앱 기능을 소개하는 문서라면 IT가 더 적절할 수 있습니다.

지도학습으로 분류기를 만들 때는 정답이 붙은 여러 문서로부터 단어와 주제의 관계 등을 계산합니다. 사람이 문서 하나하나의 모든 판단 규칙을 작성하는 대신, 데이터로부터 예측에 사용할 숫자를 얻습니다. 라벨 없이 문서 사이의 비슷함을 찾는 비지도학습도 있으며, 4.2절에서 비교합니다.

사람이 하는 일도 남아 있습니다. 무엇을 분류할지, 어떤 자료를 쓸지, 어떤 학습 방법으로 계산할지, 결과를 어떻게 평가할지는 사람이 설계합니다. 데이터로 배웠다고 문맥을 언제나 올바르게 구분하는 것은 아닙니다.

**생각해 보기:** 회사 규정의 특정 번호가 포함됐는지만 확인한다면 문자열 검색으로 충분할 수 있습니다. 여러 표현으로 쓰인 문서의 주제를 구분한다면 머신러닝을 검토할 이유가 생깁니다.

7절의 점수표 예제로 이 차이를 연결해 봅시다. 사람은 ‘IT 문서에 나온 단어에는 1을 더한다’는 학습 절차를 정합니다. 그 절차로 문서와 정답을 계산하면 ‘배터리’의 점수 1을 얻습니다. 이후 ‘배터리 수명 안내’라는 새 문서에서는 이미 얻은 1을 읽어 IT로 예측합니다. 마지막으로 별도 정답과 비교해 맞았는지 확인합니다.

이 흐름은 **문서와 정답 → 학습으로 얻은 점수 → 새 문서의 예측 → 정답과 비교한 평가**입니다. 사람이 직접 ‘배터리가 있으면 IT’라는 최종 규칙을 적는 방식과 달리 점수 자체를 자료에서 구했습니다. 다만 사람이 학습 절차와 살펴볼 단어를 정한 매우 단순한 모델입니다. 데이터가 스스로 목적을 정하거나 모든 판단 방법을 만들어 내는 것은 아닙니다.

## 4. 데이터와 모델을 구분하기

### 4.1 입력과 라벨

지도학습 문서 분류에서 **입력은 문서 내용이고, 라벨은 그 문서에 붙인 정답 종류**입니다. 먼저 이 비교용 예제로 용어를 익힙니다.

| 입력 문서 | 라벨 |
| --- | --- |
| 새 스마트폰의 카메라 기능을 소개한다 | IT |
| 기업의 올해 매출과 영업이익을 발표한다 | 경제 |
| 축구 선수가 결승전에서 득점했다 | 스포츠 |

이렇게 정답을 붙인 예제로 배우는 방식을 **지도학습**이라고 합니다. 뒤의 점수표와 라벨링 실습은 지도학습의 기초를 이해하기 위한 것입니다. 최종 목표인 비지도 문서 군집화가 반드시 이 라벨로 학습해야 한다는 뜻은 아닙니다.

문서의 라벨은 문서가 가진 절대적인 속성이라기보다, 만들고 싶은 기능의 분류 기준에 따라 정해집니다. 예를 들어 IT 회사의 매출 기사도 ‘주요 내용이 실적이면 경제’라는 기준을 정했다면 경제가 됩니다.

### 4.2 지도학습과 비지도학습

**지도학습 분류는 ‘정해진 이름을 맞히기’, 비지도 군집화는 ‘비슷한 것끼리 모으기’로 생각하면 됩니다.** 비지도학습은 정답 라벨 없이 데이터의 패턴을 찾는 방법이고, 군집화는 그 한 종류입니다.

| 방식 | 학습에 주는 것 | 결과의 의미 |
| --- | --- | --- |
| 지도학습 분류 | 문서와 정답 라벨 | 정해진 종류 중 하나를 예측 |
| 비지도 군집화 | 정답 라벨이 없는 문서 모음 | 정한 유사성 기준에 따라 비슷한 문서를 같은 그룹으로 묶음 |

이번 목표의 **N은 만들 그룹의 수**입니다. 예를 들어 N=3이면 세 그룹으로 묶도록 정합니다. N을 3으로 정했다고 그 그룹이 자동으로 IT·경제·스포츠가 되는 것은 아닙니다. 모든 군집 방법이 그룹 수를 미리 요구하는 것도 아니지만, 이 과정에서는 N을 지정하는 방법부터 배웁니다.

군집 결과의 ‘그룹 0’, ‘그룹 1’ 같은 번호는 구별을 위한 표시입니다. 그룹 0이 항상 IT라는 뜻은 아니며, 다시 묶으면 번호나 구성도 달라질 수 있습니다. 사람은 결과를 본 뒤 **각 그룹의 대표 문서와 핵심어를 검토하고 이름을 붙입니다.** 이름은 내용을 설명하기 위한 것이지, 처음부터 학습에 넣은 정답이 아닙니다.

한국어 ‘배터리 절약 설정’과 영어 ‘battery-saving setting’은 표현이 달라도 비슷한 내용입니다. 최종 모델에서는 이러한 문서가 언어별로만 갈라지지 않고 내용에 따라 가까워지는지도 확인해야 합니다. 문서를 숫자로 표현하고 비슷함을 계산하는 방법은 뒤의 Chapter에서 배웁니다.

군집화에서 ‘비슷하다’는 기준은 중요합니다. 문서에 쓰인 언어만 비교하면 한국어 문서끼리 모일 수 있습니다. 반면 내용의 비슷함을 잘 표현하면 언어가 다른 배터리 문서도 함께 모을 수 있습니다. 정답 라벨이 없다는 것은 아무 기준 없이 묶는다는 뜻이 아닙니다. 사람이 고른 문서 표현과 비교 방법이 결과에 영향을 줍니다. 문서에 뚜렷한 주제 구분이 없으면 N개로 나눈 결과도 유용하지 않을 수 있습니다.

### 4.3 특성과 모델과 파라미터

컴퓨터는 텍스트를 계산 가능한 숫자로 바꿔 처리합니다. 모델이 판단에 사용하는 입력 정보를 **특성 feature**이라고 부릅니다. 단순한 예에서는 특정 단어가 있는지 여부가 특성이 될 수 있습니다.

**모델은 입력에서 결과를 계산하는 구조와 그 구조에 들어가는 숫자를 포함합니다.** 학습 과정에서 조정하거나 데이터로부터 구하는 숫자를 파라미터라고 합니다. 가중치는 파라미터의 한 종류입니다.

실습의 단어 점수는 자료에서 얻는 파라미터이지만, N=3처럼 사람이 정하는 그룹 수는 학습·계산 방법을 정할 때 선택하는 설정입니다.

뒤의 지도학습 비교 실습에서는 다음과 같은 작은 모델을 만듭니다.

| 구성 | 실습에서의 역할 |
| --- | --- |
| 특성 | ‘스마트폰’, ‘배터리’, ‘선수’, ‘경기’가 있는지 |
| 파라미터 | 각 단어에 붙는 점수 |
| 예측 계산 | 입력에 있는 단어들의 점수를 더하기 |
| 출력 | IT, 스포츠 또는 판단 보류 |

실제 언어모델은 훨씬 많은 숫자와 복잡한 계산을 사용합니다. 그렇지만 **입력을 계산에 넣어 결과를 얻는다**는 큰 흐름은 같습니다.

문서 군집화에서도 내용을 숫자로 바꾸어 서로 비교할 수 있어야 합니다. 모델이 학습한 기준에 따라 문서 내용을 `[0.2, 0.7, ...]` 같은 숫자 목록으로 표현한 것을 **문서 임베딩 embedding**이라고 부릅니다. 이런 숫자 목록을 벡터라고 하며, 문서를 임베딩으로 바꾸는 모델이 문서 표현 모델입니다. 각 숫자가 그대로 IT 점수나 정답 확률을 뜻하지는 않습니다.

내용이 비슷한 문서의 숫자 표현도 가깝게 나오도록 학습된 모델을 사용하면, 쓰인 단어가 달라도 비슷한 내용을 찾는 데 도움이 됩니다. 아래 숫자는 이 원리를 보여 주려고 직접 만든 **설명용 좌표**입니다. 실제 임베딩이나 성능 측정값은 아닙니다.

| 문서 | 언어와 내용 | 설명용 숫자 두 개 |
| --- | --- | --- |
| A | 한국어: 배터리를 오래 쓰는 설정을 소개한다. | [0.90, 0.10] |
| B | 영어: This setting helps the battery last longer. | [0.85, 0.15] |
| C | 한국어: 축구팀의 우승 소식. | [0.10, 0.90] |

B는 ‘이 설정은 배터리를 더 오래 쓰도록 돕는다’는 뜻입니다. 두 좌표의 차이를 살펴보는 이 단순 예에서는 A와 B의 차이가 각각 0.05로 작습니다. A와 C의 차이는 각각 0.80으로 큽니다. 따라서 언어가 다른 A·B가, 같은 한국어인 A·C보다 내용상 가까운 상황을 표현합니다. A와 B를 묶고 C를 따로 두면 ‘언어별 묶음’과 다른 결과가 됩니다.

실제 임베딩은 더 많은 숫자를 사용할 수 있으며, 각 숫자에 ‘배터리’나 ‘축구’처럼 사람이 읽을 수 있는 뜻이 정해져 있지는 않습니다. 숫자를 임의로 만들어 넣는 대신 학습된 문서 표현 모델로 계산합니다. 숫자가 크다는 이유만으로 더 좋은 문서나 높은 정답 확률을 뜻하지도 않습니다.

가까움은 선택한 모델과 비교 계산의 기준입니다. 사람이 원하는 주제의 비슷함과 다를 수 있습니다. 따라서 A·B처럼 같은 내용의 한영 문서가 가까운지, A·C처럼 같은 언어이지만 내용이 다른 문서가 구분되는지 함께 확인합니다. 실제 표현 모델과 거리·유사도를 계산하는 방법은 Chapter 5에서 배웁니다. 여기서는 **문서를 숫자로 표현해야 계산으로 비교할 수 있고, 그 표현이 묶음의 품질에 영향을 준다**는 관계를 이해하면 됩니다.

## 5. 학습과 추론은 언제 일어날까요

### 5.1 학습은 데이터에서 계산 기준을 얻는 과정입니다

학습에서는 데이터를 사용해 모델의 파라미터를 구하거나 조정합니다. 지도학습 신경망에서는 예측과 정답의 차이를 줄이도록 숫자를 조정합니다. 이 과목의 작은 지도학습 실습에서는 정답 문서에 등장한 단어를 정해진 방법으로 세어 점수를 얻습니다. 군집화는 정답 라벨 대신 데이터 사이의 비슷함을 활용합니다. 학습 방법에 따라 구체적인 계산은 다릅니다.

**데이터와 학습 절차 → 학습된 모델**이라는 흐름을 기억하세요. 지도학습 분류의 데이터에는 정답 라벨도 포함됩니다.

### 5.2 추론은 학습한 기준으로 새 입력을 처리하는 과정입니다

학습이 끝나면 새로운 문서를 넣어 결과를 계산합니다.

**새 문서와 학습된 모델 → 예측 결과**가 추론입니다.

일반적인 추론에서는 결과를 한 번 출력했다고 모델의 가중치가 자동으로 바뀌지 않습니다. 사람이 결과를 수정하더라도, 그 피드백으로 다시 학습하는 과정이 따로 있어야 모델에 반영됩니다.

### 5.3 평가는 목적에 맞게 결과를 확인하는 과정입니다

정답이 있는 지도학습 분류에서는 예측과 정답을 비교합니다. 시험을 볼 때 정답지를 먼저 보지 않듯, 입력만 모델에 주고 예측을 구한 다음 따로 보관한 정답과 비교합니다. 아래 표는 이 지도학습 예제의 과정입니다.

| 상황 | 무엇을 하는 중인가요? |
| --- | --- |
| 정답 문서로 단어 점수를 구한다 | 학습 |
| 구한 점수로 새 문서를 분류한다 | 추론 |
| 예측과 따로 보관한 정답을 비교한다 | 평가 |
| 결과가 틀려 학습 자료를 보완하고 점수를 다시 구한다 | 추가 학습·재학습 |

![지도학습 예제에서 모델을 학습한 뒤 새 입력으로 추론하고 예측과 정답을 비교하는 흐름](assets/training_inference.png)

*그림 3. 지도학습 분류 예제로 본 학습, 추론, 평가. 일반적인 추론에서는 학습된 숫자를 바꾸지 않습니다. 군집화와 요약은 작업 목적에 맞는 평가를 사용합니다.*

학습에 쓴 문서를 잘 맞히는 것만으로 충분하지 않습니다. 처음 보는 문서에도 배운 기준을 적용해 잘 처리하는 능력을 **일반화**라고 합니다. 반대로 학습 자료에만 있는 우연한 특징까지 지나치게 맞춰 새로운 자료에서 성능이 나빠지는 현상을 **과적합**이라고 합니다. 학습 결과가 좋아져도 새로운 자료의 결과가 함께 좋아지는지 확인해야 하는 이유입니다.

지도학습 분류에서는 자료를 역할별로 나누어 이를 확인합니다.

| 자료 | 역할 |
| --- | --- |
| 학습 자료 | 모델의 파라미터를 구하거나 조정할 때 사용 |
| 검증 자료 | 학습 중간에 결과를 살펴보고 학습 방법이나 모델을 선택할 때 사용 |
| 최종 평가 자료, 테스트 자료 | 선택을 마친 모델을 따로 보관한 자료로 마지막에 확인 |

#### 서로 다른 원문 100개를 나누는 예

한국어와 영어로 된 문서 100개와 각 문서의 정답 라벨을 준비했다고 가정합니다. 복사본이나 같은 원문의 번역을 별도 원문으로 세지 않은 수입니다. 이 자료를 학습 60개, 검증 20개, 최종 평가 20개로 나눕니다. **60:20:20은 역할을 이해하기 위한 예시이며 정해진 표준 비율이 아닙니다.** 자료의 양과 목적에 따라 조정해야 합니다.

1. 학습 60개로 단어 점수를 구합니다. 검증·최종 평가 문서의 정답은 이 점수 계산에 넣지 않습니다.
2. 검증 20개의 입력으로 예측하고, 그 정답과 비교합니다. 예를 들어 살펴볼 단어를 네 개로 정한 방법과 여섯 개로 정한 방법을 비교해 고릅니다. 각 방법의 점수는 학습 60개에서만 구합니다.
3. 방법과 모델을 선택하면 더 이상 바꾸지 않고, 따로 보관한 최종 평가 20개로 마지막 결과를 확인합니다.

순서는 **학습 → 검증으로 비교·선택 → 최종 평가**입니다. 최종 평가 결과를 보고 단어 목록을 계속 고치면, 가중치를 그 자료로 직접 학습하지 않았어도 그 자료에 맞는 방법을 고르게 됩니다. 그런 결과는 완전히 새로운 문서에 대한 평가라고 보기 어렵습니다. 그 결과를 계기로 다시 개선한다면, 마지막 확인에는 개발 과정에서 쓰지 않은 새 평가 자료가 필요합니다. 검증 자료에만 맞추면 같은 문제가 생길 수 있습니다.

#### 섞이면 안 되는 것은 무엇일까요?

원문 A를 앞부분 A-1과 뒷부분 A-2로 잘랐다고 합시다. A-1은 학습에, A-2는 최종 평가에 넣으면 문장이나 내용이 겹칠 수 있습니다. 복사한 문서나 A를 번역한 문서를 반대쪽에 넣어도 처음 보는 내용인지 판단하기 어려워집니다. 이렇게 독립적으로 남겨야 할 평가 자료의 정보가 학습이나 선택 과정에 들어가 결과를 부풀리는 문제를 **데이터 누수, 데이터 혼입**이라고 부릅니다.

먼저 복사본을 정리하고, 같은 원문에서 나온 조각·번역문은 하나의 원문 묶음으로 관리합니다. **그 묶음 전체를 학습·검증·최종 평가 중 한쪽에만 넣습니다.** 원문 묶음을 세 자료에 배정한 뒤, 각 자료 안에서 필요한 조각을 만듭니다. 파일명이 다르다는 이유만으로 서로 다른 자료라고 판단하지 않습니다.

![서로 다른 원문 100개를 학습 60개, 검증 20개, 최종 평가 20개로 나누고 검증으로 선택한 모델을 마지막에 확인하는 흐름](assets/dataset_split.png)

*그림 4. 자료를 역할별로 분리하는 예. 같은 원문의 복사본·조각·번역문은 같은 쪽에 둡니다. 60:20:20은 설명용 비율이며, 원문 수와 조각 수는 구분합니다.*

#### 무작위로 나누면 항상 충분할까요?

실제로 한영 문서를 처리할 목적이라면 세 자료에 한국어·영어와 주요 주제가 어떻게 들어갔는지 확인합니다. 최종 평가에 한국어 IT 문서만 있다면 영어 스포츠 문서를 잘 처리하는지는 알 수 없습니다. 대표성은 앞으로 처리할 문서의 특징을 평가 자료가 얼마나 잘 담는지를 뜻합니다. 언어와 주제뿐 아니라 길이·형식 등이 실제 사용 자료와 크게 다른지도 살펴봅니다. 단순히 파일을 무작위로 섞는 것만으로 대표성이 보장되지는 않습니다.

원문 20개에서 18개를 맞히면 18÷20=90%입니다. 이때 한 개의 정오답만 바뀌어도 5%포인트가 달라집니다. 따라서 작은 평가 자료에서 얻은 90%를 모든 문서의 성능이라고 단정하지 않습니다. 여러 종류의 새 자료를 충분히 모으고, 전체 결과와 언어·주제별 실패를 함께 확인해야 합니다. 자료를 평가용으로 더 남기면 결과를 판단하는 데 도움이 되지만 학습에 쓸 자료는 줄어듭니다. 이 균형을 생각하며 자료의 수와 분리 방법을 정합니다.

군집화에서는 미리 정답 이름이 없을 수 있습니다. 대표 문서들이 내용상 비슷한지, 언어만 같아서 묶인 것은 아닌지 등을 검토합니다. 그룹 번호가 사람의 번호와 같다는 이유로 정확하다고 판단하지 않습니다. 요약에서는 핵심 내용이 담겼는지와 원문의 사실을 바꾸지 않았는지를 확인합니다.

### 5.4 사전학습과 추가학습과 추론

문서 AI를 만들 때 모든 것을 처음부터 학습할 필요는 없습니다. 이미 학습된 모델에서 출발하면 기존에 배운 언어 패턴을 활용할 수 있기 때문입니다.

| 구분 | 쉬운 뜻과 예 |
| --- | --- |
| 사전학습 pretraining | 많은 자료로 기본 패턴을 미리 배우는 과정. 언어모델이라면 본문의 일부나 다음 부분을 정답으로 삼아 예측하는 작업 등으로 학습 |
| 추가학습 fine-tuning | 이미 학습한 모델을 내 작업의 자료로 더 조정하는 과정. 문서와 원하는 요약 예시를 사용해 요약 작업에 맞출 수 있음 |
| 추론 inference | 준비된 모델로 새 문서의 결과를 계산하는 과정. 일반적인 추론에서는 모델의 가중치를 바꾸지 않음 |

**사전학습 모델을 불러오기 → 우선 추론해 평가하기 → 필요할 때 추가학습 → 다시 평가하기**로 접근합니다. 모델에 ‘이 문서를 요약해 줘’라는 요청을 넣는 것만으로 추가학습이 되는 것은 아닙니다. 추가학습은 가중치를 바꾸는 별도 과정입니다.

#### 문서 요약 모델로 생각해 보기

기존 모델이 제품 안내 문서를 요약할 때 배포일을 자주 빠뜨린다고 가정합시다. 다음은 실제 성능 측정값이 아닌, 작업 순서를 설명하는 사례입니다.

| 단계 | 하는 일 | 모델의 가중치 |
| --- | --- | --- |
| 원래 결과 확인 | 기존 모델에 문서를 넣어 핵심 누락·사실 오류를 기록 | 그대로 사용 |
| 필요성 판단 | 요청에 배포일을 포함하라고 적어도 부족한지, 원하는 요약 기준이 명확한지 확인 | 그대로 사용 |
| 추가학습 | 학습용 원문과 원하는 요약을 짝지어, 예시 요약을 예측하도록 계산하고 오차를 줄이는 방향으로 조정 | 학습 대상 가중치를 변경 |
| 검증과 최종 평가 | 검증 자료로 학습 방법을 고른 뒤, 쓰지 않은 새 문서에서 원래 모델과 결과 비교 | 평가 중에는 그대로 사용 |

예를 들어 학습용 원문이 ‘새 버전은 금요일에 배포된다. PDF 요약 기능이 추가된다’라면 원하는 요약 예시는 ‘금요일 배포되는 새 버전에 PDF 요약 기능이 추가된다’로 만들 수 있습니다. 추가학습에서는 이러한 원문·요약 쌍을 여러 개 사용해 원문을 입력으로, 원하는 요약을 학습 목표로 삼습니다. 실제 언어모델은 요약을 이루는 부분들을 순서대로 예측하는 계산 등을 사용합니다. 단순히 문서 파일을 저장하거나 정답 요약을 화면에 보여 주는 것만으로 학습되는 것은 아닙니다.

요청문에 ‘배포일을 포함해 요약해 줘’라고 적는 것은 모델에 줄 입력을 바꾸는 일입니다. 가중치를 고치는 학습과 다릅니다. 그 요청만으로 목적에 충분하다면 추가학습이 필요하지 않을 수도 있습니다. 추가학습을 하더라도 예시에만 맞추거나 원래 능력이 나빠질 수 있으므로, 실제로 개선됐는지 별도 자료로 확인합니다. 한국어 자료로만 확인한 결과를 영어에도 그대로 적용하지 않습니다.

사전학습 모델은 기존의 언어 패턴을 활용하는 출발점이지, 내 문서와 언어에서의 품질을 보장하는 완성품은 아닙니다. 여기서는 **요청해서 결과를 계산하는 것과 자료로 가중치를 조정하는 것을 구분**합니다. 실제 모델 사용과 추가학습 방법은 Chapter 5와 Chapter 7에서 배웁니다.

> 출력 예시: IT

분류 기준을 먼저 정해야 합니다. 이 문서에는 회사나 제품 가격이 언급되어도 주요 내용이 앱 기능이라면 IT로 분류할 수 있습니다.

이 분류는 정해진 종류를 맞히는 비교 예제입니다. 최종 목표의 군집화는 문서 모음에서 비슷한 내용을 찾아 N개 그룹으로 묶는 작업입니다.

### 6.2 추출 요약

원문에서 중요한 문장을 선택합니다.

> 출력 예시: 문서 관리 앱의 업데이트는 금요일에 배포된다. 이번 업데이트에는 PDF 요약 기능이 추가된다.

문장을 그대로 가져와도 중요한 문장을 빠뜨리거나, 앞뒤 문맥을 빼서 의미가 달라질 수 있습니다. 문장을 복사했다는 사실만으로 좋은 요약이 되지는 않습니다.

### 6.3 생성형 요약

원문의 내용을 바탕으로 새로운 문장을 작성합니다.

> 출력 형식 예시: 금요일 업데이트로 문서 관리 앱에 PDF 요약 기능이 추가된다.

읽기 쉬운 문장을 만들 수 있지만, 원문에 없는 정보를 넣거나 사실을 바꿀 수도 있습니다. 예를 들어 ‘토요일에 자동 번역 기능이 추가된다’는 요약은 날짜와 기능이 모두 잘못됐습니다. 이러한 오류를 환각이라고 부릅니다.

위 출력은 방식의 차이를 보여 주기 위해 직접 작성한 예시입니다. 실제 모델의 실행 결과나 성능 측정값은 아닙니다.

영어도 같은 원리로 요약합니다. 예를 들어 ‘The app update arrives on Friday. It adds PDF summaries.’를 ‘The Friday update adds PDF summaries.’로 정리할 수 있습니다. 이 교재에서는 한국어 원문은 한국어로, 영어 원문은 영어로 요약하는 예제부터 사용합니다. 요약과 다른 언어로 번역하는 작업은 구분합니다.

### 6.4 모델을 고르는 방향

기초 비교용 분류에는 작은 전용 모델을 사용할 수 있습니다. 군집화에서는 문서를 숫자로 표현하는 모델과 그 숫자로 비슷한 문서를 묶는 방법을 배웁니다. 추출 요약은 간단한 문장 점수 계산으로 시작할 수 있고, 생성형 요약은 문장을 생성할 수 있는 모델을 사용합니다. 한영 요약과 군집화는 각각의 목적에 맞게 결과를 확인합니다.

| 문서 | 내용 |

영어 읽기가 어렵다면 다음 뜻을 참고하세요. B는 ‘휴대폰에 배터리 절약 설정이 있다’, D는 ‘앱이 문서를 폴더로 정리한다’, F는 ‘축구팀이 결승전에서 이겼다’, H는 ‘농구 선수가 30점을 넣었다’입니다. 이것은 실습을 돕는 뜻풀이이며, 모델이 번역한 결과는 아닙니다.

3. 같은 문서를 다시 살펴보고 **N=3**인 세 묶음을 만듭니다. 처음의 두 묶음을 반드시 유지할 필요는 없습니다.
4. N을 바꾸니 무엇이 더 자세히 나뉘었는지, 같은 내용의 한국어·영어가 함께 묶였는지 적습니다.

| 설정 | 문서들을 묶은 결과 | 대표 문서·핵심어·그룹 이름 |
| --- | --- | --- |
| N=2 |  |  |
| N=3 |  |  |

**이것은 군집화의 목적을 이해하는 손실습입니다.** 사람이 내용을 읽고 묶은 것이므로 실제 군집 모델을 학습하거나 정확도를 평가한 실험은 아닙니다. 11.3절의 묶음은 가능한 예시일 뿐 유일한 정답은 아닙니다. 실제 모델이 언어보다 내용을 잘 반영하는지는 이후 별도로 검증합니다.

## 11. 실습과 확인 문제 해설

### 11.1 실습 1 점수표

| 문자열 | 처음 | A 반영 후 | B 반영 후 | C 반영 후 | D 반영 후 |
| --- | --- | --- | --- | --- | --- |
| 스마트폰 | 0 | 1 | 2 | 2 | 2 |
| 배터리 | 0 | 1 | 1 | 1 | 1 |
| 선수 | 0 | 0 | 0 | -1 | -1 |
| 경기 | 0 | 0 | 0 | -1 | -2 |

| 새 입력 | 계산 | 예측 |
| --- | --- | --- |
| 배터리 수명 안내 | 1 | IT |
| 선수 경기 기록 | -1 + -2 = -3 | 스포츠 |
| 스마트폰으로 경기 촬영 | 2 + -2 = 0 | 판단 보류 |
| 김치찌개 만드는 방법 | 해당 문자열 없음, 합계 0 | 판단 보류 |
| 경기도 버스 노선 안내 | ‘경기’가 포함되어 -2 | 스포츠로 오판 |

스마트폰과 경기가 함께 있는 문서는 점수가 서로 상쇄됐습니다. 요리 문서는 아는 문자열이 없어 0이 됐습니다. 같은 점수여도 이유가 다릅니다.

‘경기도’의 일부를 경기로 찾는 것은 문자열 포함만 검사하는 방식의 한계입니다. 단어 분리와 문맥이 중요해지는 이유를 보여 줍니다. 새로운 표현을 잘 처리할 수 있는지는 별도로 평가해야 합니다.

사람이 고른 것은 문자열 목록과 점수를 얻는 절차입니다. 실제 점수는 학습 자료에서 계산했습니다. 추론할 때는 점수표를 바꾸지 않았습니다.

### 11.3 라벨 없이 묶기 실습 예시

아래 이름은 문서들을 묶은 다음 내용을 설명하려고 붙인 것입니다. 그룹 번호나 이름을 먼저 정답으로 준 것이 아닙니다.

| 설정 | 묶은 문서 | 나중에 붙인 설명용 이름 |
| --- | --- | --- |
| N=2 | A·B·C·D | 휴대폰·앱 기능 |
| N=2 | E·F·G·H | 스포츠 경기 |
| N=3 | A·B | 배터리 설정 |
| N=3 | C·D | 문서 정리 앱 |
| N=3 | E·F·G·H | 스포츠 경기 |

예를 들어 N=3의 A·B 묶음에서는 A를 대표 문서로, ‘배터리·절약·설정’을 핵심어로 고를 수 있습니다. 한국어·영어의 문장이 완전히 같지 않아도 비슷한 주제를 다룬다는 점을 살펴봅니다.

N=2에서는 휴대폰과 앱의 기능을 넓게 묶었고, 이 N=3 예시에서는 둘을 더 세부적으로 나눴습니다. 다른 가능한 N=3 결과는 A·B·C·D, E·F, G·H로 묶어 ‘기기·앱 기능 / 축구 / 농구’로 설명하는 것입니다. **N만으로 그룹의 주제나 세부 수준이 하나로 결정되지는 않습니다.** 실제 군집 계산에서도 N을 바꾸면 이전 그룹이 그대로 유지된다는 보장은 없습니다.

문서를 언어별로만 나눴다면 서로 다른 내용이 한 그룹에 섞일 수 있습니다. 이 과정의 목표는 같은 내용의 한영 문서도 함께 살펴볼 수 있는 군집화입니다. 다만 이 손실습의 결과가 특정 모델이 그렇게 동작한다는 증거는 아닙니다. 모델 평가는 Chapter 6에서 별도로 배웁니다.

### 11.5 확인 문제 해설

1. AI가 가장 넓은 분야이며, 머신러닝은 AI의 한 접근법이고 딥러닝은 머신러닝의 한 종류입니다.
2. 점수를 얻는 절차는 사람이 설계한 학습 방법이고, 최종 점수표는 데이터에서 구한 파라미터입니다. 점수표와 예측 계산을 함께 사용해 작은 모델을 구성합니다.
3. 이미 얻은 파라미터로 결과를 계산하므로 추론입니다.
4. 자동으로 학습하지 않습니다. 피드백을 모아 재학습하거나 모델을 갱신하는 과정이 별도로 있어야 합니다.
5. 회사의 업종보다 문서의 주요 내용을 기준으로 정했기 때문입니다. 이 예에서는 매출과 이익이 중심입니다.
6. 아닙니다. 핵심 누락이나 문맥 손실이 생길 수 있습니다.
7. 아닙니다. 준비된 모델로 결과를 계산하는 것은 추론입니다. 추가학습은 자료를 사용해 가중치를 조정하는 별도 과정입니다.
8. 검증 자료로 단어 목록이나 모델을 골랐다면 그 선택에 이미 영향을 준 자료입니다. 별도로 보관한 최종 평가 자료로 선택을 마친 모델을 확인해야 합니다. 최종 평가에서 틀린 문서를 보고 목록을 바꾼 뒤 같은 자료로 다시 평가하면, 처음 보는 문서에서의 결과라는 근거가 약해집니다.
9. 아닙니다. 설계에 따라 기존 세 종류 중 하나를 출력할 수 있습니다. 보류·범위 밖 처리는 별도로 마련해야 합니다.
10. 충분하지 않습니다. 처음 보는 문서에서도 결과를 확인해야 합니다.
11. 아닙니다. 이 목표의 비지도 군집화는 문서의 정답 주제 라벨 없이 비슷한 문서들을 묶습니다. 결과를 검토하거나 평가할 때 사람이 참고 정보를 붙이는 일과 학습에 정답을 주는 일은 구분합니다.
12. 아닙니다. N은 만들 그룹 수입니다. 그룹 0은 구별용 번호이며 의미가 고정되지 않습니다. 사람이 대표 문서와 핵심어를 검토해 설명용 이름을 붙입니다.
13. 그렇다고 단정할 수 없습니다. 문서의 내용에 따라 묶였는지 확인해야 합니다. 같은 내용의 한영 문서가 갈라지고, 다른 내용의 같은 언어 문서만 모였다면 목표에 맞지 않을 수 있습니다.
14. 파일명이 달라도 내용이 겹치면 평가가 부풀 수 있습니다. 같은 원문의 복사본·조각·번역문을 묶어 학습·검증·최종 평가 중 한쪽에만 배정합니다.

## 12. 선택 실습 Python으로 같은 점수표 만들기

손 실습을 이해했다면 다음 코드를 Python 3에서 실행해 보세요. 지도학습 비교 예제인 실습 1과 같은 점수표를 만드는 코드이며, 비지도 군집 코드가 아닙니다. 기본 라이브러리만 사용합니다. 문자열 목록과 학습 절차는 코드에 정하고, 점수는 학습 자료로부터 구합니다.

```python
words = ["스마트폰", "배터리", "선수", "경기"]
training_docs = [
    ("스마트폰 배터리 개선 소식", "IT"),
    ("스마트폰 신제품 발표", "IT"),
    ("선수 경기 인터뷰", "스포츠"),
    ("경기 결과 발표", "스포츠"),
]

# 학습: 정답 자료로 점수를 구합니다.
scores = {word: 0 for word in words}
for text, label in training_docs:
    change = 1 if label == "IT" else -1
    for word in words:
        if word in text:
            scores[word] += change

def predict(text):
    # 추론: 학습한 점수를 읽기만 합니다.
    total = sum(scores[word] for word in words if word in text)
    if total > 0:
        return "IT", total
    if total < 0:
        return "스포츠", total
    return "판단 보류", total

new_docs = [
    "배터리 수명 안내",
    "선수 경기 기록",
    "스마트폰으로 경기 촬영",
    "김치찌개 만드는 방법",
    "경기도 버스 노선 안내",
]

print("학습한 점수:", scores)
for text in new_docs:
    label, total = predict(text)
    print(f"{text} -> {label} (점수 {total})")
```

예상 출력:

```text
학습한 점수: {'스마트폰': 2, '배터리': 1, '선수': -1, '경기': -2}
배터리 수명 안내 -> IT (점수 1)
선수 경기 기록 -> 스포츠 (점수 -3)
스마트폰으로 경기 촬영 -> 판단 보류 (점수 0)
김치찌개 만드는 방법 -> 판단 보류 (점수 0)
경기도 버스 노선 안내 -> 스포츠 (점수 -2)
```

### 바꿔 보기

1. `new_docs`에 문서를 추가합니다. 예측 결과를 보고 점수표가 자동으로 바뀌는지 확인하세요.
2. 학습 자료에 `("배터리 스마트폰 기능", "IT")`를 추가하고 프로그램을 처음부터 다시 실행합니다.
3. 두 번째 실행에서는 스마트폰 3, 배터리 2가 됩니다. ‘스마트폰으로 경기 촬영’의 합은 1이 되어 IT가 됩니다. 정답 자료가 예측 기준에 영향을 준다는 뜻이며, 품질이 좋아졌다는 증거는 아닙니다.
4. 학습 자료의 스포츠 문서 하나를 IT라고 잘못 표시하면 어떻게 될지 예측하고 실행합니다. 실제로 잘못된 학습이므로 변경한 라벨은 실습 후 되돌립니다.

이 점수는 예측 확률이나 신뢰도가 아닙니다. 점수가 크다는 이유만으로 실제로 더 정확하다고 결론 내리지 않습니다. Python·문서 데이터 처리는 Chapter 2에서, 머신러닝·군집화 기초는 Chapter 3에서 배웁니다.

- [ ] 설명용 좌표와 실제 모델의 임베딩을 구분하고, 같은 언어보다 같은 내용이 가깝게 표현되는 예를 들 수 있다.

이해가 막히면 모든 용어를 다시 외우기보다 실습 1의 점수표로 돌아가 ‘지금 숫자를 만드는 중인가, 이미 만든 숫자를 쓰는 중인가’를 확인하세요.

다음 Chapter 2에서는 Python·NumPy의 기본 계산을 익히고, 실제 텍스트 파일을 읽어 한국어·영어 문서 데이터를 준비합니다. 이번에 배운 입력과 숫자 표현을 코드로 다뤄 보는 단계입니다. TF-IDF나 역전파를 미리 이해해야 이번 과목을 마칠 수 있는 것은 아닙니다.
