## 최종 목표와 학습 범위

**목표 1 · 문서 요약 모델 설계:** 한국어·영어 문서의 핵심 내용을 원문 언어로 요약하는 모델과 처리 흐름을 설계한다.

**목표 2 · 비지도 학습 모델 설계:** 문서 내용을 보고 N개 카테고리로 묶는 모델을 설계한다. 정답 카테고리 라벨 없이 유사한 문서를 묶는 군집화를 사용한다.

N은 설정하는 그룹 수이며, 원하는 주제가 자동으로 발견된다고 가정하지 않는다. 대표 문서·핵심어를 사람이 검토해 그룹의 의미와 이름을 정한다. 처음에는 한 문서를 하나의 군집에 배정하고 여러 주제가 섞인 문서는 실패 사례로 분석한다.

**대상과 환경:** Python과 AI의 기초부터 시작한다. 입력은 한국어·영어 TXT와 텍스트를 추출할 수 있는 PDF다. PC·Mac 또는 Colab에서 학습·비교한 뒤 Kotlin 앱의 CPU에서 검증한다. Colab은 브라우저로 접속해 클라우드 컴퓨터에서 Python을 실행하는 환경이다. 사진 속 글자를 읽는 OCR은 후속 범위다.

**도달 수준:** 기본 목표는 기존 모델·알고리즘을 이해하고 조합·비교·평가·배포하는 활용·설계 중급이다. 요약 모델 추가학습은 선택 심화이며, 작은 학습 실험과 원본 대비 평가까지 수행한다. 새 대규모 모델을 방대한 자료로 처음부터 학습시키는 과정은 포함하지 않는다.

## 학습 방법과 POC 진입 조건

각 Chapter는 **쉬운 이론 → 작은 예제 → 단원 실습 → 이해·평가 확인** 순서로 진행한다. 기간보다 완료 기준으로 다음 단계에 진입한다. 작은 예제에서는 한 개념을, 단원 실습에서는 그 과목의 기능을 익힌다.

**설명 원칙:** 전문 용어는 쉬운 뜻과 함께 익힌다. 중요한 정의·작동 원리·성립 조건·한계를 생략하지 않으며, 예제를 실행하는 방법과 왜 그런 결과가 나오는지를 함께 배운다. 아래의 이론 범위는 학습할 항목이며, 세부 계산은 해당 Chapter에서 순서대로 설명한다.

POC는 여러 개념을 결합해 실제 문서에서 설계의 가능성과 한계를 검증하는 시제품이다. 예제 실행 성공만으로 POC를 완료하지 않는다. 필요한 이론·단원 실습·평가 학습을 마친 뒤 다음 조건을 확인한다.

- 입력·출력, 알고리즘의 역할, 왜 해당 방법을 사용하는지 설명할 수 있다.
- 예제의 문서·설정을 직접 바꾸고 결과를 재현하며 차이를 설명할 수 있다.
- 좋은 결과와 실패 사례를 구분하고, 비교할 자료와 평가 기준을 정할 수 있다.

## Chapter 1. AI와 머신러닝 기본 개념

**교재 PDF:** [AI와_머신러닝_기본_개념.pdf](chapter1/AI와_머신러닝_기본_개념.pdf)

**배우는 목적:** AI가 맡을 역할과 두 최종 모델의 입력·출력·실패 상황을 구체화한다.

**이론 범위:** AI·머신러닝·딥러닝의 관계, 데이터와 모델, 데이터에서 구하거나 조정하는 숫자인 파라미터를 익힌다. 학습·추론·평가, 정답을 주는 지도학습과 정답 없이 패턴을 찾는 비지도학습, 추출·생성 요약, PC 학습과 기기 추론을 구분한다.

**이해할 원리:** 학습에서는 데이터로 계산 기준을 얻고, 추론에서는 준비된 기준으로 새 입력을 처리한다. 군집화의 그룹 번호와 사람이 붙이는 주제 이름은 다르며, 요약은 자연스러운 문장인지와 원문의 사실을 지키는지를 따로 확인한다.

**작은 예제:** 라벨이 있는 점수표 분류와 라벨 없이 문서를 묶는 활동을 비교한다. 같은 주제의 한국어·영어 문서를 함께 살펴보고 군집 번호와 카테고리명이 다른 개념임을 확인한다.

**단원 실습:** 손으로 문서를 N=2와 N=3으로 묶고 대표 문서로 이름을 정한다. 문서를 요약한 뒤 누락·사실 오류를 찾고 두 모델의 기능 명세를 적는다.

**완료 기준:** 학습과 추론, 지도·비지도 학습을 자신의 말로 설명하고 N의 의미·요약 형태·실패 처리 방향을 정한다. 이 단계의 손실습은 POC가 아니다.

## Chapter 2. Python·NumPy와 문서 데이터 처리

**예정 PDF:** `Python·NumPy와_문서_데이터_처리.pdf` · **학습 전**

**배우는 목적:** 문서를 읽고 정리하며, 모델이 계산할 수 있는 데이터와 배열을 준비한다.

**이론 범위:** Python 변수·함수·리스트·딕셔너리·파일 읽기와 실행 환경을 익힌다. 추가 기능 묶음인 패키지, 숫자 배열을 다루는 NumPy, 배열의 크기·모양(Shape), 원소 고르기(인덱싱), 간단한 집계를 배운다. TXT·PDF 글자 추출, 계산에 맞게 입력을 정리하는 전처리와 문장 분리도 연습한다.

**이해할 원리:** 파일에서 꺼낸 글자가 곧 모델 입력은 아니다. 문서·문장·숫자 배열로 바꾸면서 문서가 뒤섞이거나 핵심 내용이 빠지지 않는지 확인한다. 어떤 정보가 남고 사라지는지는 숫자 표현 방식에 따라 다르다. 학습 자료는 모델을 맞추는 데, 검증 자료는 설정을 고르는 데, 최종 평가 자료는 선택이 끝난 결과를 확인하는 데 사용한다.

**작은 예제:** 문서 여러 개를 목록으로 읽고 문장 수·길이를 구한다. 한·영 문장에서 줄바꿈·띄어쓰기·문장 경계를 확인하고 배열의 행·열이 무엇인지 설명한다.

**단원 실습:** 출처·언어·문서 ID를 기록하고 빈 입력·중복·PDF 반복 머리말을 정리한다. 원문과 정리 결과를 비교하며 문단 경계를 유지한다. 군집을 맞추는 문서 묶음과 새 문서를 구분하고, 요약 추가학습용 자료는 학습·검증·최종 평가로 나눈다.

**완료 기준:** 정리한 문서를 다시 읽어 같은 배열을 만들고, 전처리 규칙과 데이터 분리 이유를 설명한다. 군집용 자료에 정답 카테고리 라벨을 붙이는 것을 필수로 삼지 않는다.

## Chapter 3. 기초 수학과 전통적 머신러닝

**예정 PDF:** `기초_수학과_전통적_머신러닝.pdf` · **학습 전**

**배우는 목적:** 문서의 숫자 표현·유사성·군집 중심을 이해하고 간단한 비교 기준을 만든다.

**이론 범위:** 숫자 목록인 벡터, 이를 행·열로 모은 행렬, 평균·분산·거리와 벡터 방향의 비슷함을 재는 코사인 유사도를 배운다. 단어 빈도와 문서별로 두드러진 단어에 점수를 주는 TF-IDF, [K-Means](https://scikit-learn.org/stable/auto_examples/text/plot_document_clustering.html)의 중심·배정·갱신, 문장 점수를 이용한 추출 요약을 익힌다. 작은 숫자로 직접 계산한다.

**이해할 원리:** TF-IDF는 한 문서에 자주 나오면서 전체 문서에는 흔하지 않은 단어를 두드러지게 표현한다. 준비한 문서 모음에서 어휘와 단어별 문서 빈도를 구해, 흔한 단어의 비중을 낮추는 값인 IDF를 계산한다. 새 문서에도 같은 어휘·IDF를 적용한다. K-Means는 처음 정한 N개 중심에 가까운 문서를 배정하고, 각 그룹의 벡터 평균으로 중심을 다시 구하는 과정을 반복한다. 중심이 거의 변하지 않거나 정한 반복 한도에 도달하면 멈춘다. 어떤 숫자 표현과 거리 기준을 쓰는지에 따라 ‘비슷한 문서’가 달라진다.

**작은 예제:** 2차원 점의 거리와 평균 중심을 손으로 구하고, 짧은 문서를 단어 숫자로 바꿔 비슷한 문서와 중요한 문장을 고른다.

**단원 실습:** 손 계산 뒤 scikit-learn으로 TF-IDF·K-Means를 실행한다. N과 초기값을 바꾸고 핵심 문장을 원문 순서로 표시한다. 어휘가 다른 한·영 문서가 의미보다 언어로 갈릴 수 있음을 관찰한다.

**완료 기준:** TF-IDF의 학습과 새 문서 변환을 구분하고, 중심을 고정해 새 문서를 배정한다. N·초기값·전처리 변화의 영향을 설명한다. 알고리즘 전체의 직접 구현을 요구하지 않는다.

## Chapter 4. 딥러닝 기초와 PyTorch

**예정 PDF:** `딥러닝_기초와_PyTorch.pdf` · **학습 전**

**배우는 목적:** 신경망을 만들고 학습시키는 도구인 PyTorch를 사용한다. 학습 코드를 읽고 검증 결과에 따라 설정을 조정하는 기초를 익힌다.

**이론 범위:** 숫자 배열인 Tensor와 그 모양(Shape), 가중치가 있는 계산 층들을 연결한 신경망을 배운다. 층의 계산값에 비선형 변환을 적용하는 활성화 함수, 입력에서 예측을 계산하는 순전파, 예측 오차를 수치화한 손실(Loss)을 익힌다. 가중치를 바꾸면 오차가 어떻게 달라지는지 나타내는 기울기(gradient), 이를 계산하는 자동미분, 가중치를 갱신하는 최적화 도구(optimizer)를 연결한다. 한 번에 처리하는 자료 수(batch size), 전체 학습 자료를 훑은 횟수(epoch), 갱신 크기를 조절하는 학습률을 익힌다. 학습·검증 모드, 과적합과 저장·재실행도 다룬다.

**이해할 원리:** 활성화 함수는 단순한 직선 관계만으로 표현하기 어려운 패턴을 신경망이 다루게 한다. 예측 → 손실 계산 → 기울기 계산 → 가중치 갱신을 반복하며 손실을 줄이는 방향을 찾는다. 손실에서 앞선 층 방향으로 미분값을 연결해 각 가중치의 기울기를 구하는 과정이 역전파이며, PyTorch의 자동미분 기능으로 수행한다. 학습 자료의 오차만 줄고 새 자료에서 나빠지는 과적합이 생길 수 있으므로 검증 결과를 따로 확인한다. 미분은 작은 숫자 변화가 오차를 어떻게 바꾸는지부터 이해한다.

**작은 예제:** 입력 → 예측 → 손실 → 기울기 계산 → 가중치 갱신 → 검증의 한 바퀴를 따라간다. 작은 지도학습 예제는 신경망 학습 원리를 익히기 위한 비교 실습이다.

**단원 실습:** 학습률·반복 횟수·배치 크기를 하나씩 바꾸며 학습·검증 오차를 기록한다. 모델을 저장·불러오고 학습에 쓰지 않은 자료의 결과를 확인한다.

**완료 기준:** 학습 코드의 각 단계와 과적합을 설명하고, 고정한 실행 조건에서 결과를 재현한다. 오차가 줄지 않을 때 입력·학습 설정·검증 자료를 점검한다.

## Chapter 5. 자연어 처리와 사전학습 모델 이해

**예정 PDF:** `자연어_처리와_사전학습_모델_이해.pdf` · **학습 전**

**배우는 목적:** 사람이 쓰는 언어를 컴퓨터로 다루는 자연어 처리의 기초를 익힌다. 문서 임베딩 모델과 문장을 생성하는 요약 모델의 역할을 구분하고 적합한 후보를 선택한다.

**이론 범위:** 텍스트를 토큰이라는 처리 단위와 번호로 바꾸는 tokenizer를 익힌다. 시작·끝 등 역할을 알리는 특수 토큰, 길이를 채우는 padding, 한도를 넘는 부분을 자르는 truncation을 배운다. 문맥에 따라 토큰 사이의 관련성을 계산하는 Transformer, 의미를 숫자 벡터로 표현하는 [다국어 문장 임베딩](https://sbert.net/docs/sentence_transformer/pretrained_models.html#multilingual-models), 토큰·문장·문서 벡터의 통합과 정규화, 긴 문서 분할을 다룬다.

**이해할 원리:** 사전학습 모델은 이미 많은 자료에서 구한 가중치를 가져와 사용한다. 임베딩 모델은 내용을 비교할 벡터를 만들고, 여기서 사용하는 생성 모델은 다음 토큰 후보를 계산하며 요약문을 만든다. 여러 토큰·조각의 벡터를 합치는 방법도 결과에 영향을 준다. 정규화는 벡터의 원소 개수는 유지하면서 전체 크기를 일정하게 맞추는 것이다. 모델에 맞는 tokenizer가 필요하며, 잘린 부분의 정보는 입력에서 빠진다.

**작은 예제:** 같은 주제의 한·영 문서와 주제가 다른 문서의 벡터를 비교한다. 생성 모델로 짧은 문서를 요약하고, 임베딩 벡터가 요약문 자체는 아니라는 점을 확인한다.

**단원 실습:** 긴 문서를 나눠 문서 벡터로 합친다. 모델별 한·영 지원·입력 한도·라이선스·메모리·실행 도구 지원을 확인한다. 추가학습 전에 작은 입력으로 변환·기기 실행 가능성을 먼저 시험한다.

**완료 기준:** 전처리부터 출력까지의 흐름과 임베딩·생성 모델의 차이를 설명하고, 선택한 후보의 품질·기기 제약과 한계를 기록한다.

## Chapter 6. 문서 임베딩과 비지도 군집화 설계

**예정 PDF:** `문서_임베딩과_비지도_군집화_설계.pdf` · **학습 전**

**배우는 목적:** 문서를 N개 카테고리로 묶는 모델의 표현·군집화·명명·갱신 절차를 설계한다.

**이론 범위:** 문서 벡터 통합·정규화, N과 처음 계산을 시작할 중심을 정하는 초기값, 반복 실행, 대표 문서·핵심어를 배운다. 같은 군집의 문서가 얼마나 가깝고 다른 군집과 얼마나 떨어져 있는지 살피는 [실루엣 점수](https://scikit-learn.org/stable/modules/clustering.html#silhouette-coefficient), 내용의 의미 검토, 새 문서·범위 밖 입력을 다룬다. N개 그룹과 자연스러운 주제 수가 같다고 가정하지 않는다.

**이해할 원리:** 문서의 숫자 표현과 중심이 정해지면 새 문서를 가까운 중심에 배정할 수 있다. K-Means는 다루려는 주제 밖의 문서도 기존 군집에 배정하므로 ‘모름’ 처리는 따로 설계한다. 실루엣이 좋아도 원하는 주제로 묶였다는 보장은 없으므로 대표 문서를 읽어 확인한다.

**작은 예제:** 같은 N에서 TF-IDF와 임베딩을 비교하고, 같은 표현에서 초기값을 바꾼다. 실루엣은 2≤군집 수<문서 수인 조건을 확인하고 보조 지표로 사용한다.

**단원 실습:** 언어보다 주제로 묶이는지 대표 문서를 읽는다. 다시 학습하면 군집 번호가 바뀔 수 있으므로 문서가 함께 묶이는 관계를 비교한다. 중심 고정 후 새 문서 배정과 어울리지 않는 문서의 처리·군집 갱신 방안을 적는다.

**완료 기준:** 선택 이유와 실패 사례를 설명하고 N·표현·평가 조건을 고정해 재현할 수 있으면, Chapter 1~6의 준비 상태를 확인한 뒤 POC A로 진행한다.

## Chapter 7. 문서 요약 모델 설계와 추가학습

**예정 PDF:** `문서_요약_모델_설계와_추가학습.pdf` · **학습 전**

**배우는 목적:** 요약 모델·입력 처리·평가를 설계하고 한·영 요약의 품질과 실행 비용을 판단한다.

**이론 범위:** 원문 문장을 고르는 추출 요약과 새 문장을 만드는 [생성 요약](https://huggingface.co/docs/transformers/tasks/summarization)을 비교한다. 작업·출력 조건을 전달하는 지시인 프롬프트, 출력 길이와 생성 설정, 긴 문서 분할·조각 요약·최종 통합을 배운다. 원문에 없는 내용과 누락을 찾고, 사람이 작성한 참고 요약과 비교하는 점수와 직접 검토를 함께 사용한다.

**이해할 원리:** 프롬프트나 출력 설정을 바꾸는 것은 입력·실행 조건의 변경이며 모델 가중치를 학습하는 것과 다르다. 문서를 나눠 요약할 때는 조각별 정보와 전체 문맥을 다시 합쳐야 한다. 참고 요약과 비슷하다는 점수만으로 원문의 사실을 지켰다고 판단하지 않는다.

**작은 예제:** 짧은 문서를 원문 언어로 요약하고 프롬프트·출력 길이를 하나씩 바꾼다. 자연스러운 문장과 사실에 맞는 문장이 다른 기준임을 확인한다.

**단원 실습:** 짧은 문서 → 설정 변경 → 긴 문서 분할·통합 순서로 진행한다. 문서 앞·중간·끝의 핵심 내용 보존과 반복·누락을 검토한다. 같은 문서에서 추출·생성 요약의 품질과 비용을 비교한다.

**완료 기준:** 모델·처리 흐름·평가표·실패 예시를 재현하고 설명할 수 있을 때 POC B로 진행한다. 요약문 작성 예제를 따라 하는 단계와 모델 선택·평가 단계를 구분한다.

**선택 심화 · 추가학습 중급:** 문서–요약 쌍을 준비하고 학습·검증·최종 평가 자료를 분리한다. 이미 학습된 모델을 목적에 맞는 자료로 더 학습하는 추가학습을 수행한다. 기반 모델의 가중치는 고정하고 작은 추가 가중치를 학습하는 [LoRA](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)도 선택할 수 있다. 원본 대비 개선·악화와 비용을 확인하며, 용어 이해나 코드 실행만으로 완료하지 않는다. 학습 결과의 기기 배포 가능성도 먼저 확인한다.

## Chapter 8. Android 온디바이스 배포와 경량화

**예정 PDF:** `Android_온디바이스_배포와_경량화.pdf` · **학습 전**

**배우는 목적:** 선택한 군집·요약 경로를 기기에서 재현하고 품질·속도·메모리 제약에 맞춘다.

**이론 범위:** 모델·tokenizer·어휘·IDF·군집 중심을 저장하고 전처리·특수 토큰·padding·분할·정규화 조건을 맞춘다. 모델의 실행 형식을 바꾸는 변환, 실제 계산을 수행하는 실행 도구인 ONNX Runtime의 CPU 실행, 숫자를 더 적은 비트로 표현하는 [양자화](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)를 배운다. 비동기 실행·취소·자원 해제·오류 상태를 다루며, 생성 모델을 지원하는 실행 도구는 후보 선정 단계에서 확인한다.

**이해할 원리:** 같은 모델이라도 입력을 다르게 만들면 결과가 달라질 수 있으므로 PC와 앱의 처리 조건을 맞춘다. 양자화는 모델 숫자의 저장 부담을 줄이지만 품질이 달라질 수 있고, 실행 메모리·속도 개선도 기기와 실행 도구에 따라 다르다. 파일 크기만으로 판단하지 않고 실제 실행에서 확인한다.

**작은 예제:** 동일한 배포 모델과 전처리 조건으로 PC·Android의 입력·중간 벡터·군집 배정·추출 요약을 비교한다. 벡터는 정한 허용 오차로 확인한다. 원본 → 변환 → 양자화의 정밀도·품질 변화는 별도로 평가한다.

**단원 실습:** 비행기 모드와 한·영 문서로 실행·취소·재실행을 확인한다. 같은 입력 길이·출력 조건에서 최초 로딩과 준비 후 실행 시간을 나누고, 프로세스 최대 메모리와 모델·tokenizer 파일 크기를 기록한다. 앱 연결은 에뮬레이터, 성능 판단은 실기기로 검증한다.

**완료 기준:** 동일한 배포 모델의 PC 기준과 군집 배정·추출 요약 결과를 대조하고, 허용 오차·차이의 원인과 품질·지연·메모리를 설명할 수 있을 때 POC C로 진행한다. 생성형 요약은 실기기 지원·자원·품질을 확인해 적용하고, 부족하면 측정 근거와 추출 요약 대체 경로를 남긴다.

### POC A · 비지도 군집 모델 설계 검증

**입력:** 주제와 언어 구성을 기록한 문서 묶음, 고정한 N, 모델을 맞추는 데 쓰지 않은 새 문서.

**진행:** 같은 문서와 N으로 TF-IDF·다국어 임베딩을 비교한다. 여러 초기값에서 문서 관계와 대표 문서를 검토하고 그룹의 의미·이름을 정한다. 선택한 표현과 중심을 저장한 뒤 새 문서를 배정한다.

**완료:** 재실행 가능한 코드·전처리·모델 설정·중심을 남긴다. 언어별·주제별 군집 품질, 안정성, 범위 밖 문서와 실패 예시를 설명하고 선택 이유를 설계안에 적는다. 그룹 수를 맞췄다는 사실만으로 완료하지 않는다.

### POC B · 문서 요약 모델 설계 검증

**입력:** 학습에 사용하지 않은 한·영 짧은 문서와 긴 문서, 사람이 정리한 핵심 내용 또는 참고 요약.

**진행:** 동일한 문서에서 추출·생성 요약을 비교한다. 원문 언어, 입력 분할·최종 통합, 출력 길이·모델 설정을 고정한다. 사실성·핵심 내용 보존·누락·반복·처리 시간을 평가한다.

**완료:** 요약 코드·모델·tokenizer·설정과 평가표를 저장한다. 좋은 결과와 실패 예시를 포함한 설계안을 남기고 다른 사람이 같은 문서로 재실행할 수 있게 한다. 추가학습을 했다면 원본과 학습 후 모델을 같은 최종 평가 자료로 비교한다.

### POC C · Android 통합 검증

**입력:** A·B에서 선택한 모델·처리 흐름과 고정한 한·영 평가 문서. 군집은 준비된 중심에 새 문서를 배정하는 방식을 기본으로 한다.

**진행:** 문서 선택 → 텍스트 추출 → 군집 배정·요약 → 결과 표시를 연결한다. 오프라인에서 동일 배포 모델의 PC 기준과 군집 배정·추출 요약을 대조하고 차이를 설명한다. 취소·연속 실행과 실기기 자원을 측정하며 생성형 요약은 기기에 적합한 경로를 별도로 시험한다.

**완료:** 대상 기기·Android 버전·입출력 조건·로딩/실행 시간·최대 메모리·파일 크기를 기록한다. 두 기능의 품질과 실패 처리를 설명하고, 생성 모델을 적용하거나 대체한 근거를 남긴다. 기기마다 동일한 생성 속도를 가정하지 않는다.

## 평가·기록과 최종 도달 기준

- 자료·전처리·모델 버전·초기값·실행 조건을 기록하고 고정 자료로 비교한다. 모델 선택에 쓰는 자료와 최종 평가 자료를 구분하며, 같은 원문의 복제·번역본이 양쪽에 섞이지 않게 확인한다.
- 군집은 대표 문서·문서 관계·안정성과 점수를 함께 검토한다. 군집 번호를 정답 카테고리처럼 취급하지 않으며, 한·영 문서가 언어보다 내용으로 묶이는지 확인한다.
- 요약은 언어별 사실성·핵심 내용 보존·누락을 직접 검토한다. 자동 점수만으로 사실성을 판단하지 않는다. 추가학습·최종 평가 문서는 분리한다.
- 이론을 설명하고, 작은 실습을 독립적으로 바꾸며, POC에서 대안을 비교·선택하고, Android에서 두 기능의 실행 근거를 제시하면 기본 활용·설계 중급을 완료한다.
- 요약 추가학습까지 수행했다면 데이터 준비·학습·검증·원본 대비 평가·배포 확인을 별도로 기록해 선택 심화 완료를 구분한다.
