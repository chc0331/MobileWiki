# 학습 자료 작성과 검사

`study/`의 Markdown을 원본으로 삼고 PDF를 함께 관리한다. PDF 생성 도구는 본문, 표, 실습, 해설과 코드를 옮기고 과목 교재에 표지, 목차, 북마크와 페이지 번호를 붙인다.

학습 자료를 작성·수정·검수하기 전에 [에이전트 지침](../AGENTS.md)과 [AI 교재 집필 규칙](../AUTHORING_RULES.md)을 반드시 읽는다. 집필 규칙의 12개 기준과 완료 점검표를 내용 검수에 사용한다. 이 안내의 검사 명령은 파일·링크·PDF 등을 확인하며 설명 품질까지 자동으로 판정하지 않는다.

전체 계획서만 예외로 `study/README.md`를 `study/학습 계획.pdf`로 만든다. 계획서에는 별도 표지와 차례를 넣지 않는다.

## 준비

검사 도구는 Python 3 표준 라이브러리만 사용한다. PDF와 그림 생성에는 `tools/requirements.txt`의 패키지가 필요하다. 저장소 안에 가상 환경을 둘 때는 Git에서 제외된 `_workspace/venv`를 사용한다.

```sh
python3 -m venv _workspace/venv
_workspace/venv/bin/python -m pip install -r tools/requirements.txt
```

macOS에서는 시스템의 한글 글꼴과 Menlo를 기본으로 사용한다. Linux에서는 NanumMyeongjo, NanumGothic, DejaVuSansMono의 TrueType 글꼴을 사용할 수 있다. 다른 환경에서는 다음 환경 변수에 사용 가능한 글꼴 파일 경로를 지정한다. 폰트 파일은 저장소에 복사하지 않는다.

| 환경 변수 | 용도 |
| --- | --- |
| `PDF_BODY_FONT` | PDF 한글 본문용 TrueType 글꼴 |
| `PDF_SANS_FONT` | PDF 제목·표·한글 코드용 TrueType 글꼴 |
| `PDF_CODE_FONT` | 코드의 영문·숫자용 고정폭 TrueType 글꼴 |
| `CJK_FONT` | 그림의 한글 글꼴. macOS 이외에서는 명시적으로 지정 |

### Chapter 2 실습 입력 PDF 재생성

Chapter 2에서 읽는 `study/chapter2/examples/it02_ko.pdf`는 교재가 아니라 실습 입력 파일이다. 이 PDF를 다시 만들 때는 위 가상 환경의 Python으로 제작 스크립트를 실행한다.

```sh
_workspace/venv/bin/python study/chapter2/examples/make_sample_pdf.py
```

새 PDF를 만든 뒤에는 Chapter 2 교재 2.1절의 실습 코드를 다시 실행한다. 두 페이지의 글자가 추출되는지 확인하고 교재 9.2절에 적힌 반복 머리말 제거 수와 문단 길이 기준 결과를 비교한다.

## 새 Chapter 작성 순서

1. `study/README.md`의 Chapter 번호와 과목명을 확정한다. 새 과목은 `study/chapter{번호}/`를 만들고 과목명의 공백을 `_`로 바꾼 이름으로 Markdown을 저장한다. 첫 줄은 `# 과목 {번호} {과목명}`으로 쓴다.
2. 로드맵에 해당 Chapter의 배우는 목적, 이론과 원리, 작은 예제, 단원 실습, 완료 기준을 연결한다. 교재가 없으면 `` **예정 PDF:** `파일명.pdf` · **학습 전** ``으로 적는다.
3. 교재는 학습 목표 → 문제와 친숙한 사례 → 쉬운 정의와 작동 원리 → 작은 예제 → 입력을 바꿔 보는 실습 → 결과와 실패 이유 → 핵심 요약·완료 점검·다음 학습으로 연결한다. 개념이 바뀌는 지점에는 생각할 질문을 둔다. 처음 나오는 용어에 쉬운 뜻을 붙이고 계산의 의미와 적용 조건도 설명한다. 과목 문서에서 전체 계획서는 `../README.md`로 연결한다.
4. 그림은 해당 과목의 `assets/`에 두고 Markdown 본문에 이미지와 설명을 함께 넣는다. 그림 생성 코드를 바꿨으면 그림부터 다시 만든다. 교재 Markdown을 완성하면 로드맵에 과목 Markdown 링크를 추가하고 등록 줄을 새 PDF 링크로 바꾸며 `학습 전`을 지운다. 그다음 PDF 생성 도구로 교재와 학습 계획 PDF를 함께 갱신한다. `study/README.md`를 고칠 때마다 `study/학습 계획.pdf`도 다시 만든다.
5. 집필 규칙의 완료 점검표와 [내용 검수 기준](../skills/document-content-review/SKILL.md)으로 설명·예제·실습·해설을 대조한다. `humanize-korean`으로 윤문한 최종 Markdown에 맞춰 PDF를 갱신한다. `python3 tools/check_study.py`를 실행하고 오류가 있으면 출력된 파일과 줄을 고친다. PDF 본문과 모든 페이지를 직접 확인한다.

## 기존 자료 수정 순서

1. 집필 규칙과 로드맵을 읽고 대상 Chapter의 목표, 관련 절·예제·그림·문제·해설을 확인한다. 바꿀 내용과 보존할 정의·계산·조건을 정한다.
2. 필요한 본문과 내부 참조를 고친다. 필수 원리와 짧은 계산·코드는 본문에 남기고 긴 구현은 단계별로 나누거나 선택 심화·예제 파일로 안내한다. Chapter의 범위를 벗어나는 앱 설계를 앞당겨 넣지 않는다.
3. 내용 검수와 윤문을 마친 뒤 변경한 그림과 PDF를 갱신한다. 코드를 바꿨거나 여러 블록으로 나눴다면 안내한 실행 순서로 실행하고 결과·해설과 대조한다.
4. 링크·PDF 짝·등록 상태 검사와 PDF 본문·전체 페이지 검토를 수행한다. 실제로 수행한 검증, 미확인 항목, 최종 변경 파일을 확인한다. 임시 산출물은 Git에 추가하지 않는다.

검사 도구는 파일을 수정하지 않는다. 상대 링크와 그림 파일, Markdown·PDF 짝, Chapter 번호·파일명·교재 등록 상태를 확인하며 학습 문서의 외부 링크를 오류로 알린다. 그림의 설명이 충분한지, PDF의 내용과 배치가 좋은지는 사람이 확인해야 한다.

과목의 `examples/`에 둔 실습 입력 PDF는 교재가 아니므로 같은 이름의 Markdown을 요구하지 않는다. 학습 문서에서 그 PDF로 연결한 상대 링크는 검사한다.

## 현재 PDF 생성기가 읽는 Markdown

- `#`부터 `####`까지의 제목, 일반 문단, `- ` 목록과 `1. ` 번호 목록, `> ` 인용문, `| `로 시작하는 표, 삼중 백틱 코드 블록을 사용한다.
- 링크는 `[설명](상대/파일)` 형식으로 쓰고 그림은 한 줄 전체에 `![대체 설명](assets/그림.png)` 형식으로 쓴다. 그림 아래에 `*그림 1. 설명*`을 두면 PDF에서도 그림과 설명이 함께 배치된다.
- 문장 안에서는 `**굵게**`, `` `코드` ``, `[설명](상대/파일)`을 처리한다. 중첩 목록, 참조형 링크, HTML 태그, 표 안의 `|` 문자는 현재 생성기의 변환 범위 밖이다. 본문을 이 형식으로 작성하고 PDF에서 빠진 내용이 없는지 확인한다.

## PDF 생성

그림을 추가·수정한 경우 그림을 먼저 생성하고 PDF를 갱신한다.

```sh
_workspace/venv/bin/python tools/build_study_figures.py
_workspace/venv/bin/python tools/build_study_pdfs.py
```

PDF 생성 도구는 모든 `study/**/*.md`를 처리한다. 원문의 텍스트 요소가 PDF에 같은 순서로 포함됐는지 확인하며 PDF의 상대 링크는 다른 PDF를 향하도록 변환한다. `README.md`로 향하는 링크는 이름이 변경된 학습 계획 PDF로 연결한다.

본문은 11pt, 행간은 교재 18.5pt·계획서 18pt를 사용하고 표는 9.5pt를 기본으로 한다. `#### 함께 풀기`, `#### 직접 해보기`, `#### 결과와 해석` 등의 제목은 역할을 구분하는 배경과 함께 표시한다. 짧은 목록은 함께 배치하되, 높이가 큰 목록은 항목 사이에서 페이지를 나눌 수 있다. 그림 바로 앞의 짧은 계산 목록은 그림·설명과 함께 배치한다. 교재 차례와 북마크에서 절 제목을 누르면 해당 페이지로 이동한다.

## 시각 검토

변경하거나 새로 만든 PDF는 모두 Poppler의 `pdftoppm`으로 전체 페이지를 이미지로 렌더링한다. 아래 명령은 계획서와 Chapter 1 교재의 예시다. 다른 교재도 입력 PDF와 출력 이름을 바꿔 같은 방법으로 확인한다. 임시 파일은 저장소 밖에 둔다.

```sh
mkdir -p /tmp/mobilewiki-pdf-review
pdftoppm -r 120 -png "study/학습 계획.pdf" /tmp/mobilewiki-pdf-review/roadmap
pdftoppm -r 120 -png study/chapter1/AI와_머신러닝_기본_개념.pdf /tmp/mobilewiki-pdf-review/chapter1
```

Fontconfig가 별도로 설정된 환경에서는 해당 환경의 `FONTCONFIG_FILE`을 지정한다. 검토 이미지는 Git에 추가하지 않는다.

다음 항목을 모든 페이지에서 확인하고 수정한 PDF를 다시 렌더링한다.

- 한글, 문장부호, 체크박스와 코드의 글자가 깨지지 않는지
- 제목이 본문과 함께 있고 표·그림·코드가 잘리지 않는지
- 반복 표 머리행과 실습 빈칸이 읽고 쓰기 편한지
- 실습과 정답 해설이 구분되고 목차와 북마크가 실제 페이지로 이동하는지
- 상대 링크, 그림과 PDF가 원본 Markdown의 최신 내용과 일치하는지
