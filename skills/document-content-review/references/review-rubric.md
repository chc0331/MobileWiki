# 항목별 내용 검수 기준

문서에 실제로 있는 요소와 독자에게 필요한 내용에 적용한다. 표의 모든 요소를 각 절에 새로 추가하는 체크리스트로 사용하지 않는다.

## 설명과 활동의 연결

| 대조할 부분 | 판단할 내용 |
| --- | --- |
| 제목·목적 ↔ 본문 | 제목이 약속한 개념·절차·판단을 본문이 실제로 설명하는가? 다른 주제로 옮겨 갔다면 연결과 이유가 있는가? |
| 설명 ↔ 예제 | 예제가 설명한 규칙을 사용하며, 새 규칙이나 선수 지식을 갑자기 요구하지 않는가? |
| 예제·설명 ↔ 독자의 작업 | 실습·확인 질문·실행 지시가 이 항목의 원리를 연습하거나 적용하게 하는가? 문제와 해설이 서로 맞는 것만으로 이 연결을 통과시키지 않는다. |
| 작업 ↔ 결과·해설 | 지시한 각 질문과 단계에 답하는가? 필요한 계산·판단의 이유가 설명되어 있는가? |
| 목적 ↔ 완료 기준 | 학습이나 작업을 완료했다는 기준으로 해당 목적의 달성 여부를 확인할 수 있는가? 단순 실행 성공과 이해·품질 확인을 혼동하지 않는가? |

입력·주제·표현이 달라져도 배운 원리로 풀 수 있다면 정상적인 응용이다. 확장에 필요한 조건을 설명한 경우도 허용한다. 반대로 정답 자체가 타당해도 절의 원리와 무관한 활동이라면 연결의 문제다. 최소 수정은 활동을 목적에 맞추거나, 필요한 연결을 본문에 보완하는 방식으로 제안한다.

## 정확성과 재현 가능성

- **정의와 범위:** 용어의 뜻, 종류 간 포함 관계, 입력과 출력이 정확한가? 방법을 나열한 문장을 하나의 방법에 대한 정의로 잘못 묶지는 않았는가?
- **규칙과 계산:** 단어·배열·단위의 순서, 부호, 초기값, 누적·초기화 여부, 기준값과 경계 조건을 확인한다. 중간 계산부터 결과까지 직접 대조한다. 반올림·근삿값은 문서가 정한 기준으로 판단한다.
- **주어진 정보:** 결과를 얻는 데 필요한 값·판단 규칙·실행 조건이 제공되는가? 여러 결과가 가능한데 하나만 정답으로 확정하지 않는가? 해설에만 새 규칙이 나타나면 정보 부족을 살핀다.
- **주장과 증거:** 예시 몇 개로 전체 성능·원인·보장 조건을 단정하지 않는가? 가능성, 필요 조건, 충분 조건을 바꾸어 말하지 않는가? 전문적·최신 주장을 확인해야 한다면 직접 근거를 찾고 적용 조건도 대조한다.
- **단순화와 실제 동작:** 손으로 만든 모형·가정한 예·실제 관측 결과가 구분되는가? 비유와 학습용 단순화를 실제 원리 전체로 일반화하지 않는가?

계산 결과가 맞아도 본문에 없는 규칙이 있어야 도달할 수 있다면 설명은 충분하지 않다. 먼저 문서 전체에서 해당 규칙과 안내를 찾는다. 실제로 없으면 필요한 조건의 누락이고, 다른 절에 있으나 찾기 어렵다면 위치 안내의 문제다. 외부 자료를 열지 못해 존재 여부를 모르는 경우에는 확인 필요로 둔다.

## 문서 안의 일관성

- 본문·표·그림·캡션·코드의 입력, 표기, 수치, 계산 순서와 결과를 함께 비교한다. 실제 그림과 코드 본문을 확인하며 캡션이나 예상 출력만으로 대신하지 않는다.
- 같은 용어·기호·번호가 문서 전체에서 같은 의미인지 확인한다. 용도가 달라지면 그 위치에서 명시했는지 살핀다.
- 다른 절·문제·정답·파일을 가리키는 참조가 실제 내용과 맞는지 확인한다. 참조한 문서의 필요한 부분만 추가 확인하고 검수 범위를 프로젝트 전체로 넓히지 않는다.
- 작성 예정임을 밝힌 단원·자료와 현재 존재해야 하는 링크를 구분한다. 미래 단원의 세부 절을 이미 존재하는 것처럼 안내한다면 지적한다.
- 그림·표·독립된 예제의 전제가 본문과 다르면 그 차이가 분명히 표시되어 있는지 살핀다. 서로 다른 전제를 명시한 사례를 숫자가 다르다는 이유로 모순으로 판정하지 않는다.

## 독자가 이해하고 적용할 수 있는지

- 독자의 수준에서 처음 필요한 전문 용어·약어·기호의 뜻을 설명하는가? 처음부터 아는 지식을 독자에게 다시 가르치라고 요구하지 않는다.
- 무엇을 입력하고 무엇을 판단·작성·계산해야 하는지, 결과가 어떤 형태인지 알 수 있는가?
- 설명한 원리와 예제 사이에 계산·판단 단계가 빠져 있지 않은가? 한 문장에 서로 다른 개념을 압축해 관계를 읽기 어렵게 만들지 않는가?
- ‘앞에서’, ‘뒤의 표’, ‘그 값’ 같은 표현이 여러 대상을 가리킬 수 있는가? 충분히 가까워 대상이 명확하면 기계적으로 번호 참조를 요구하지 않는다.
- 독자가 입력 한 가지를 바꿨을 때 같은 규칙으로 결과를 예상하고 이유를 설명할 수 있는가? 설명만으로 판단하기 어렵다면 어떤 정보를 추가해야 하는지 구체화한다.
- 설명을 쉽게 고치면서 조건·한계·중요한 차이를 지우지 않는가? 표현 취향이나 문장 길이만으로 필수 수정을 만들지 않는다.

## 판정의 근거와 오탐 방지

- **필수 수정:** 실제 충돌, 틀린 계산, 명시된 목적과 다른 활동, 재현에 필요한 정보의 부재처럼 문서에서 확인한 문제다. 원인과 위치를 제시할 수 있어야 한다.
- **설명 개선:** 내용은 성립하지만 지정된 독자가 따라가기 어려운 구간이다. 어느 단계에서 왜 막히는지와 더 명확한 대안을 함께 쓴다.
- **확인 필요:** 열지 못한 자료, 미확인 사실, 선택되지 않은 작성 의도 때문에 확정할 수 없는 사안이다. 추정을 확정 오류로 옮기지 않는다.

지적하기 전에 관련 정의·전제·참조를 다시 확인한다. 짧은 인용을 문맥과 분리해 의미를 바꾸지 않는다. 문제없는 항목과 정상적인 응용을 보존하며, 전체를 읽지 못했다면 검수 완료 범위를 한정한다. 평가의 근거는 구체적인 발견 사항이며 임의의 점수나 실제로 수행하지 않은 독자 시험이 아니다.
