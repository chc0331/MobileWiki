# 문서 설명 검수

문서의 각 항목이 맞는 내용을 설명하는지, 대상 독자가 설명을 따라가고 적용할 수 있는지를 검수한다. **기본 동작은 검수와 수정안 제시**다. 수정 요청 없이 원문·설정·파생 파일을 변경하지 않는다. 사용자가 수정까지 요청했다면 그 범위 안에서 반영한다.

## 문서와 독자 확인

- 요청과 문서에서 대상 독자·목적·검수 범위를 확인한다. 독자가 명시되지 않았다면 해당 분야를 처음 접하는 일반 독자를 기준으로 삼고 결과에 밝힌다.
- 제목 계층에 따라 모든 항목의 검수 목록을 만든다. 제목이 없으면 문단·목록·표 등 의미 단위로 나눈다. 같은 이름의 ‘직접 해보기’가 여러 번 나와도 상위 절과 위치로 구분한다.
- 관련 표·그림·캡션·코드·주석을 포함해 읽는다. 같은 이름의 Markdown과 PDF가 있어도 서로 최신이거나 내용이 같다고 가정하지 않는다. 실제로 확인한 파일과 형식만 검수 범위에 넣는다.
- 형식을 읽는 데 필요하면 사용 가능한 PDF·문서 도구나 스킬을 사용한다. 그림을 보지 못했거나 텍스트를 추출하지 못한 부분은 확인 불가로 남긴다. 이미지 대체 텍스트만으로 그림 내용까지 확인했다고 하지 않는다.

## 항목별 검수

상세 판단 기준은 [검수 기준](references/review-rubric.md)을 읽고 적용한다.

1. 각 항목의 제목과 목적을 정리하고 **목적 → 설명한 원리 → 예제 → 독자가 할 일 → 결과·해설**을 대조한다. 해당 문서에 있는 요소끼리 연결하며, 모든 항목에 실습이나 예제가 있어야 한다고 요구하지 않는다.
2. 문제와 정답의 일치뿐 아니라 **그 문제가 이 항목에서 배운 원리를 연습하게 하는지** 확인한다. 다른 입력을 쓰는 정상적인 응용 문제와, 연결 설명 없이 다른 목표로 넘어가는 문제를 구별한다.
3. 정의·입출력·계산·전제 조건·한계를 확인한다. 독자가 제시된 정보만으로 과정을 재현할 수 있는지 살피고, 필요한 규칙이 문서의 다른 위치에 있는지도 찾는다.
4. 표·그림·코드·다른 절을 대조해 숫자·용어·규칙·참조의 일관성을 확인한다. 전문 지식이나 최신 정보의 확인이 필요하면 공식 자료·원 논문 등 직접 근거를 확인한다. 근거를 확보하지 못한 주장은 오류로 확정하지 않는다.
5. 긴 문서는 상위 절의 목적과 관련 정의를 유지하며 구획별로 검수한다. 각 구획의 확인·부분 확인·미확인 상태를 기록하고, 마지막에 문서 전체의 용어·전제·참조와 항목 간 연결을 다시 대조한다.

## 결과 보고

기본적으로 대화에 결과를 보고한다. 보고서 파일 저장은 요청받았을 때 한다. 문제가 많은 경우 같은 원인의 지적을 묶되 실제 위치와 수정안이 빠지지 않게 한다.

- **검수 범위:** 대상 독자와 가정, 확인한 파일·항목, 부분 확인·미검수·확인 불가 범위. 문제없는 항목도 범위에 포함한다. 긴 문서는 큰 절별 확인 상태로 요약할 수 있다.
- **필수 수정:** 근거로 확인한 사실·계산 오류, 필요한 조건의 누락, 설명·예제·실습·해설 사이의 불일치.
- **설명 개선:** 의미는 성립하지만 독자의 이해나 적용을 막는 용어·순서·지시·참조와 개선안.
- **확인 필요:** 외부 근거, 열지 못한 자료 또는 작성 의도가 필요해 판정하지 못한 사항.

각 지적에는 다음을 포함한다.

- **위치:** 상위 절을 포함한 항목명 + 파일 줄 번호 또는 PDF 쪽수 등 실제로 확인한 위치
- **원문:** 문제를 보여 주는 짧은 인용. 두 부분이 충돌하면 각각 인용한다.
- **근거와 독자의 어려움:** 무엇이 어긋나며 어디서 판단·계산·수행이 막히는지 설명한다.
- **수정안:** 목적과 난도를 유지하는 최소한의 대체 문구·계산·지시를 제시한다.

수정안에 원문에 없는 수치나 규칙을 사실처럼 만들어 넣지 않는다. 선택이 필요하면 제안한 조건임을 밝히고, 의도가 불명확하면 확인할 질문이나 필요한 자료를 제시한다. 근거 없는 오류를 만들어 결과를 채우지 않는다. 문제가 발견되지 않았다면 **검토한 범위에서 발견하지 못했다**고 보고한다. 읽기 검토를 실제 독자의 이해도 시험으로 표현하지 않는다.

## 수정도 요청받은 경우

- 확인된 문제에 필요한 범위만 고친다. 오류 수정 대상 외의 개념·수치·조건·한계를 유지한다.
- 대상 프로젝트의 지침에 따라 원본을 수정하고, 지정된 윤문 절차와 PDF 등 파생 파일의 동기화·검증을 수행한다. 특정 프로젝트의 경로나 학습 구조를 다른 문서에 강제하지 않는다.
- 변경 내용을 원래 지적과 대조해 보고하고, 해결하지 못한 사실·의도·자료 문제를 남긴다.
